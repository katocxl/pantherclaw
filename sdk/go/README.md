# PantherClaw Go SDK (Apache-2.0)

`github.com/katocxl/pantherclaw/sdk/go` is the Go client of the PantherClaw Authority Protocol, PAP/1 ([docs/protocol/PAP-1.md](../../docs/protocol/PAP-1.md)). It is its own module and uses only the Go standard library.

| Package | What it does |
|---|---|
| `pap` | Wire constants. The workload key file (`ReadKeyFile`, `WriteKeyFile`, `Thumbprint`). RFC 8785 canonical JSON (`Canonical`). Strict ActionIR parsing with the action hash (`ParseAction`, `ActionHash`), so an SDK can check the action a gateway decided. Request proofs (`SignProof`), and PantherClaw's proof checks (`CheckProof`), for fake gateways in tests and for services that verify PAP/1 themselves. Workload token claims read without verifying (`ParseTokenClaims`): when to renew, and which key a token is bound to. |
| `client` | The workload client. A proof over every request, with one retry for a fresh nonce (`use_nonce`). Workload tokens renewed at the server (`WorkloadService.IssueToken`), with one retry for an expired one. `Authorize`: an agent's raw tool call through the gateway's `/sdk/{connection}` face, read by `Evaluate`: an allow or a hold must carry the canonical sdk-channel action (`action_ir`) under the action id sent, hashing to its hash; an observe answer lets only a configured built-in (`Config.Builtins`) run; on a target-enforced connection, `Result.Send` is the gateway's request, sent unchanged. `Classify` sorts an agent's tool names: MCP tools of the configured servers, built-ins, and anything else, which is never sent. Server and gateway URLs must use https (http only on loopback), and redirects are never followed. `Wait` long-polls a held call (`WorkloadService.Wait`), `Stream` follows the SSE wait stream (`GET /v1/wait/{handle}`), and `AuthorizeAndWait` waits and then resubmits the identical call with the same action id once it is ready (PAP/1 §8). It fails closed (HR-200): unreachable, timed out, an error, or an answer it cannot read or check is `CannotDecide`, never `Allow`. |
| `verifier` | Target verifier middleware for services PantherClaw reaches through a target-enforced connection (PAP/1 §10, HR-202). `Middleware` refuses a request before its handler runs unless its `PAP-Action` token was minted by PantherClaw for exactly that request. The checks are: an action-tokens key from the JWKS (fetched over https, or http on loopback only, never through a redirect) with alg `EdDSA` or `Ed25519`; `iss`; `aud`; a lifetime of at most 60 s; the hash of the exact body; operation and target through the application's `match`. Only then is the token spent once in a `ReplayStore`, keyed by its audience and `jti`. Refusals are 401, 409 for a replay, and 503 when the keys or the store cannot be reached, each as a problem document with its code. `MemoryStore` serves one replica only (`SingleReplica`) and refuses tokens issued before it started plus the 5 s skew, which a restart may have spent. `SQLStore` is shared by every replica: it uses `database/sql` with the caller's driver, so the SDK adds no dependency, and its `pap_action_tokens_seen` table (`Schema`, one row per `aud` and `jti`) takes the PostgreSQL or SQLite dialect, with `INSERT … ON CONFLICT DO NOTHING` and `Purge`, which keeps rows a minute past their keeping time for replicas whose clocks are behind. The PostgreSQL dialect is tested against a real database by the test-only module `internal/sqltest` (`task sdk:check` with the test cluster up); the SQLite dialect is tested only against a fake driver, since the SDK adds no SQLite driver. |

Every package is tested against the shared vectors in [`sdk/conformance`](../conformance), which PantherClaw generates from its own implementation. `PANTHERCLAW_CONFORMANCE_DIR` points the tests at another copy. Run them with `task sdk:check`, or with `go -C sdk/go test ./...`.
