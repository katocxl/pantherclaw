# API schema and nightly assurance

`task api:schema` generates `docs/api/pantherclaw.openapi.json` from the
repository protobuf API, using the local pinned Connect OpenAPI plugin.
`internal/apischema` then makes the schema match the server: `minimum: 0`
for every protovalidate `gte: 0` numeric field (the generator drops it), the
bodiless 415 that Connect returns for a missing or unsupported Content-Type
on every operation with a request body, `null` on request-message
properties whose default passes their rules (ProtoJSON reads null as the
default), an optional `Connect-Protocol-Version`, and no `Connect-Timeout-Ms`
(an optional header whose tiny values legitimately end in a 504).
`tools/api/openapi.override.yaml` types `Connect-Protocol-Version` as the
string it is on the wire. Generated files are reviewed and committed.

The API serves POST only (405 `Allow: POST` otherwise). JSON requests with
unknown fields are rejected; upgrade the server before clients. Binary
protobuf requests still ignore unknown fields.

The nightly workflow regenerates
the schema and rejects drift. The schema describes Connect JSON and translated
Protovalidate rules; the server still owns authorization, tenant isolation,
plan checks, step-up and cross-field validation. The source includes the full
RPC surface. Gateway mTLS, streaming and server confirmation pages retain
their dedicated integration and adversarial tests.

Start the test cluster with `task up PROFILE=test`, then run `task api:check`.
The Go integration test creates a disposable migrated database, an organisation
and a real browser session, and starts the actual API on a free loopback port.
The locked `tools/api` environment tests 14 explicit read procedures, including
M13 usage and data requests. Each must first return a schema-valid HTTP 200
with a known valid request. Positive and negative generated cases then check
the wire contract, error responses and server failures. A lost session fails
the run; an all-401 run cannot pass. No mutation is generated by this suite.
Schemathesis uses seed `130023`, 25 examples per operation and no wall-clock
Hypothesis deadline, so shared-machine pauses do not look like product bugs.

The fixture cookie is passed only in the child process environment. The
client follows cookie rotation, refuses redirects and external target URLs,
and redacts current and previous cookies from failure text. No HTTP cassettes
or credential-bearing test artifacts are published. The suite is opt-in for
ordinary integration runs (`PC_TEST_API_SCHEMA=1`) because it needs the Python
test tooling; the nightly job opts in and a missing database or tool fails.

`task test:fuzz` runs the reviewed security-parser targets for 30 seconds each
with two workers. Set `PC_FUZZ_TIME=5s` for a local smoke pass. Targets cover
action normalization, credentials, PAP proofs, package manifests, mappings,
grant bounds, untrusted display and offline evidence/data documents. Go saves
minimized failures under the package's `testdata/fuzz`; keep a reproducer when
fixing a real bug. Nightly uploads only those parser inputs on failure.

These are local and nightly assurance results, not hosted G3 or G4 evidence.
The founder must merge the workflow change after review; it is never eligible
for auto-merge.
