# ADR-0057 — Firewall gaps from the threat map

**Status:** Proposed (2026-11-04; stub, founder decisions FD4–FD7 and answers E, S, C and P; the [G0 M30](../g0/M30.md) brief records them).

**Decision.** The M28 threat map named agent-reachable techniques with no PantherClaw control. M30 adds controls for them where the firewall already sees the act, and keeps every new check able only to refuse or hold, never to widen what a grant allows: MCP access tokens bound to a client's key with DPoP for clients that register one, while standard clients keep the 5-minute bearer (HR-700..702); content signals matching decoded text (HR-703); a pgvector connector whose writes outside a writer list wait for a person and carry provenance from the permit (HR-704, HR-705); count rules limited to reads and INFERRED alerts for enumeration and scheduled sends (HR-706, HR-709); holds for shares to the public or to accounts the organization has not listed (HR-707, HR-708); digests, a drift alert, a hook route and read-only sandbox binds for agent configuration and memory files (HR-710..713, R-74); and threat-map changes that keep the map honest about narrowed triggers and connector refusals (HR-714, HR-715). Follow-ups to model connections (opt-in prompt capture, resuming an approved hold) follow M29 (HR-716, HR-717). Each control is mapped on the threat map, and the techniques it covers leave the "No PantherClaw control yet" list.
