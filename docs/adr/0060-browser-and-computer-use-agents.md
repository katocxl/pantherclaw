# ADR-0060 — Browser and computer-use agents

**Status:** Proposed (2026-11-05, with the [G0 M33](../g0/M33.md) brief, which records the founder decisions FQ33-1..4 and the coordinator decisions D974–D989). The body was completed on 2026-11-06 with M33's tests (Phase B). Runbook: [browser-agents.md](../runbooks/browser-agents.md).

**Context.** Agents now drive browsers and desktops: they open pages, fill forms, download files and click on a screen. None of that passes a PantherClaw route by itself. The hook face refuses browsers (any `Origin`), and a key kept in a browser profile would be readable by every page script and by the agent. Each of those acts needs a decision per call, allowed, held for a person or refused: this is the runtime firewall (D1205). Who the agent is keeps coming from the desktop workload key; M33 adds no identity control.

**Decision.**

*Runtime firewall.*
1. **A managed extension behind a native host** (HR-751, HR-753, HR-754; founder decision FQ33-1; D979, D980). A Manifest V3 extension in `integrations/chromium-extension` (Apache-2.0, no build step) redirects every top-level navigation to its hold page with one dynamic rule, and lets one decided navigation through on that tab with a session rule. It asks before a form submit, a download (paused at once) and a click on an element an admin marked. It asks `pclaw browser host` over Chrome native messaging. The host refuses any origin but a configured extension id, bounds messages (1 MiB in, 64 KiB per input and reply), turns each decide into one PAP/1 hook call signed with the desktop workload key with an 8-second deadline, and answers `CANNOT_DECIDE` on any error. No key lives in the browser. The extension sends only the D974 inputs (addresses, field names but never values, a download's name, type and size, a marked element's selector and label, the takeover's minutes), never screenshots, DOM, field values or page text. With no host, a disconnect, no answer or a deny, it fails closed.
2. **`pc.browser` and a site list** (HR-745, HR-748, HR-749; FQ33-2; D974..D977). Five irreversible operations deduped by `params.call`: `browser.navigate`, `browser.form.submit`, `browser.download`, `browser.click` and `browser.takeover`, on target type `browser.site` (the URL's host). A new param type `url` (printable ASCII, absolute http or https, no userinfo, stored as `normurl`) with CEL `normurl`, `urlhost` and `urlquery`. The pipeline's `browser` step holds a `pc.browser` action whose host matches no site of the org (`SITE_NOT_LISTED`); an IP host never matches, an empty list holds every site, and without its port the step holds everything. Sites (migration 00370, `BrowserService`, `pclaw browser sites`) take the owned-accounts permissions and second-person rule: adding needs a second person's security key, removing applies at once; at most 500 per org, audited, and a change moves the gateway configuration version.
3. **Secret and challenge fields** (HR-747, HR-752; FQ33-4; D978, D981). The extension refuses agent input into password, one-time-code and payment fields (by type, `autocomplete` token, name pattern or a payment-host frame) and every event in a challenge frame; managed configuration can only add hosts. A submit holding a secret field is still asked with `secret_fields: true`, and the gateway refuses it before the Authority is asked (`BROWSER_SECRET_FIELD`, a local refusal report). There is no override.
4. **Takeover** (HR-746; D982). A person takes over a tab from the toolbar popup only. The pipeline always holds `browser.takeover` for one approver (`BROWSER_TAKEOVER`); no grant, policy or exception removes it. It lasts at most 10 minutes, ends by alarm, by "Give back" or when the tab closes, and while it runs the tab is let through and the secret-field refusal is lifted.
5. **Deployment** (HR-755; D983). `pclaw browser policy generate` writes `chrome-policy.json` and `chrome-policy.reg`: force-install and pin, incognito and guest mode off, the host name and the sites' click rules. It installs nothing. `pclaw browser install-host` writes the host configuration (0600), a wrapper and a manifest naming only the given extension ids, per OS.
6. **Computer use** (HR-756..758; D984, D985). `pc.computer` `computer.input` (target `computer.desktop`, id `local`). `ComputerUseGuard` in the Python and TypeScript SDKs maps Anthropic and OpenAI computer actions onto it and acts only on an allow; screen reads are allowed locally and never sent, an unknown action is refused locally (`COMPUTER_ACTION_UNKNOWN`) and any error refuses. `guard_computer` wraps an OpenAI Agents `Computer`. The model route refuses a call declaring a client-run computer tool unless the model connection allows `computer_use` (`MODEL_COMPUTER_USE_NOT_ALLOWED`), and opt-in capture replaces each image, document or screenshot block by its type, size and digest.
7. **Cloaking compare** (HR-750, HR-759; FQ33-3; D986). After an allowed navigation on a site marked for compare, the customer's gateway fetches the page twice without cookies, as the agent and with a plain user agent, through its egress client and within fixed limits. It compares word-shingle min-hashes and reports only a mismatch, as digests and numbers (`ReportPageCompare`). The server accepts a report only from the connection's gateway for a compare site, writes `browser.cloaking_suspected` throttled per hour, and the `pc.browser.cloaking` detection alerts only. It never delays or changes a decision.

*Both.* The threat map gains surface `BROWSER` and requirement `BROWSER_EXTENSION_DEPLOYED`, `prevent.browser_sites` (AML.T0100, AML.T0131) and `prevent.browser_secret_fields` (T1696.001), and the cloaking detection carries AML.T0134 (detect, PARTIAL). T1696 and T1696.002 stay Unaddressed.

**Consequences.**
- The extension is cooperative (PARTIAL): another browser, page scripts (fetch or XHR), a scripted `form.submit()` (its navigation is still held, but a POST body is lost there) and CDP or OS input outside the hooked events are not decided (R-78). Force-install with incognito and guest off narrows that, and it does not close it.
- During a takeover nothing on that tab is decided or recorded, and the agent can still act there and read what the person types (R-79). Only the takeover request is recorded.
- The compare sees only header-based cloaking, from the gateway's network, without cookies; it is alert only (R-80).
- Computer use is decided only where the SDK wrappers are used; the model route only gates whether computer use may be declared (R-81).
- Every page of an org with an empty site list holds until an admin lists its sites; that is the intended start (FQ33-2).
- Click rules reach the browser only through Chrome policy, so the policy is generated again after a site's selectors change.
- macOS policy generation and browsers other than Chrome and Chromium are follow-ups. The extension's own tests come with its package and CI.

**Alternatives.**
- A key in the extension, calling the gateway directly (FQ33-1 chose the native host; a key in a profile is readable by page scripts and the agent).
- Holding only listed "risky" sites and letting the rest through (FQ33-2 chose to hold every unlisted site).
- Letting listed sites type into secret fields under a policy (FQ33-4 chose no override; a person does it in a takeover).
- A blocking cloaking check, or one run from PantherClaw's own network (FQ33-3 chose alert only on the customer's gateway).
- Screenshots or DOM as evidence (no page content leaves the browser).
- Deciding computer use only on the model route (it sees what the model asks for, not what the agent does on the screen).
