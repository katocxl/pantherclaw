# ADR-0047 — Compliance reports and real-agent campaigns

**Status:** Accepted (2026-11-01; G0 M25 design decisions D300–D313 and the rulings D523–D549, founder decisions H4, H6, H7 and H10; the [G0 M25](../g0/M25.md) brief records them).

**Context.** Compliance teams translate PantherClaw's records into control language by hand. The range tests policies, so it does not say whether a customer's real agent can be tricked into trying something. A framework report is easy to read as a certification, and a red-team result is easy to read as proof about a model. Both readings would break F527, PN-009.4 and F801. Packs have a closed manifest: `DecodeManifest` rejects unknown members, so a new field would break older `pclaw verify`. And a real agent talks to its model provider, which a package mapping cannot carry: there is no nested parameter type, `content` is capped at 8 KiB, face bodies at 64 KiB, and responses are buffered, while a model API sends large nested JSON and streams.

**Decision.**
1. **A pure control table** (D300). `internal/compliance/domain` maps framework to control to evidence kinds, for OWASP ASI, NIST AI RMF, the EU AI Act deployer view, ISO 42001 and SOC 2. An obligation no record reaches is listed as a gap.
2. **A report is its own pack scope** (D301, D529, HR-600, HR-604). Scope and Kind `compliance`, with a `compliance.json` file under the signed manifest's digest and its own fixed statement: "This report shows evidence and gaps. It is not a certification or statement of compliance." `pclaw verify` re-derives every control offline from the report's own inputs, and a report under another table reads as not fully checked, never passed.
3. **Evidence and gaps, nothing else** (D302, D312, D531, HR-600..603). Control states are EVIDENCED, PARTIAL, GAP and STATED. No score, percentage, total or "compliant". A person's statement is STATED and never evidence. Simulated activity is counted apart; tests alone are at most PARTIAL, and a test counts only when the server saw it hold, so a reported result is a `reported_only` gap. Each source is read under its own permission as the pack's creator, and what the creator can't read is an `outside_permission` gap.
4. **Reports stay in public core** (H7, HR-605). They are under the BSL and gated by edition at the use case: OWASP and NIST on Team, the others on Business. Export stays ClassSafety.
5. **A stored row outlives the pack** (D303, HR-606). `pc.compliance_reports` keeps framework, period and digest. The database sets the digest once, and `compliance.json` holds no time of its own, so the same records give the same digest.
6. **Tags come from the library** (D304, D529, D531, D545). Library scenarios and campaign files carry `asi` tags, each with a one-line `asi_why` citing OWASP's definition, only where the scenario exercises the risk. Customer scenarios carry none.
7. **Campaigns attack a range twin** (D305, D307, HR-611, HR-612). Only a range agent, its image pinned by digest. Results say they tested a twin, not production, and whether a scripted stand-in or a real model drove them. They have their own origin and statement and never enter an assurance pack (HR-466).
8. **The key sits beside the sandbox** (D308, H6, HR-607). A local relay outside the agent's container forwards to the one model host over verified HTTPS and adds the key. The key is read once from a file, held in memory, and never reaches the container, a log or the server. HR-213 and HR-214 are unchanged.
9. **The server binds runs and derives outcomes** (D309, D525, D543, HR-608..610). Each scenario is a step; every run of the twin made while a step is open, and every descendant of such a run, is bound to it by the database. Every bound run counts and the worst outcome wins. A scenario with no bound run is NOT_EXERCISED. A step past its bounds is `RUN_TOO_LARGE` unless an ALLOWED was already read. An edge report stays NOT_ROUTED_REPORTED.
10. **A narrow model route, a written exception to HR-075** (D313, H10, HR-613..615). A gateway model face forwards the agent's bytes unchanged, with streaming, to a model relay. It serves only a simulated connection marked as a relay, only for a range agent's run during an open campaign, only to the run's one model host, within 8 MiB each way and 256 MiB a run. It makes no ActionIR, decision or transaction. The server records counts, bytes and host, never a body. HR-075 applies unchanged to every other route.

**Consequences.**
- An auditor sees gaps as gaps, so a first report will look thin. ASI01 and ASI06 read as gaps from tests until a scenario injects instructions or poisons memory or context.
- Older `pclaw verify` fails a compliance pack on its statement. Verify with `pclaw` M25 or later.
- HR-225's secret scan does not cover the model route. Planted bait, canaries included, can reach the customer's own model provider. The real key never reaches the agent: the relay adds it after the agent's bytes, outside the container.
- A manual run of the twin during a campaign is bound to the open step and counted, so the runbook says not to start one.
- A gateway of this release reports a relay as LOCAL_RELAY, which an older server refuses. Upgrade the server before gateways.
- No real model provider has been called in tests. A real model run is a "Prove it" step.
- Repeat campaign runs make no regression claim, unlike `--baseline` on the range (HR-226).

**Alternatives.** A compliance score (F797, and it reads as a claim); a new manifest field (breaks older `pclaw verify`); reports in a private repository (H7); the key inside the container (HR-213, H6); a model hosted by PantherClaw (H4); campaigns against production (HR-220); runner-supplied outcomes or run lists (a runner could leave out the bad run); campaign results in assurance packs (HR-466); model calls through package mappings (they cannot carry the traffic); no model route at all (no real agent could run).
