# ADR-0056 — Model connections: the prompt checked and forwarded, tokens reserved by estimate and settled by usage

**Status:** Accepted (2026-11-04; founder decisions Q1–Q5, FQ-A, FQ-B and FQ-C; the [G0 M29](../g0/M29.md) brief records them).

**Context.** A coding agent run in `pclaw sandbox run` could not reach its model. Five things blocked it: the edge refuses every host without a mapped connection, and no connection package existed for a model provider; the edge strips the agent's key; `pclaw sandbox run` had no way to pass settings in; the edge and the gateway's HTTP face cap bodies at 64 KiB; and neither streams, with a 2-minute timeout. Budgets counted money and action counts only, so nothing measured or capped the tokens an agent spends. M25 added a narrow model route for campaigns ([ADR-0047](0047-compliance-reports-and-real-agent-campaigns.md), HR-613..HR-615): a range agent's run, during an open campaign, through a relay that holds the key beside the sandbox, with bytes forwarded unchanged and no decision, no secret scan and no metering. A prompt cannot be an ActionIR parameter: ActionIR caps strings at 64 KiB, and ADR-0047 rejected model calls through package mappings for that reason.

**Decision.**
1. **Model connections** (Q1, D811, HR-690). A new connection kind `model`, backed only by the packages `pc.anthropic` (Messages, token counting, models) or `pc.openai` (Chat Completions, Responses, models; OpenAI-compatible servers and Azure OpenAI's v1 API). The gateway holds the provider key as a sealed credential and places it only on requests to the connection's own host. The agent never holds a key: the edge strips every credential the agent sends, as HR-213 requires, and a per-session placeholder set by `pclaw` goes unreported (D815). Anthropic and OpenAI key formats join the edge's detector and the gateway's outbound scanner (D816).
2. **The prompt checked and forwarded** (FQ-A, D812, HR-691). The gateway parses a model request as strict JSON (one object, no duplicate member names, valid UTF-8, nesting at most 256, at most 16 MiB). It decides on the request's metadata and the sha256 of the re-encoded body, and forwards exactly that re-encoded body to the connection's base URL plus the operation's fixed path, with listed headers only. Its only edit is adding the connection's max-tokens value when the request has none. The decision, any approval and the receipt bind the body's hash. This is a written exception to HR-075, for model connections only (HR-691); HR-075 applies unchanged to every other route.
3. **Operations and parameters** (D813, D813a). Six operations: `anthropic.messages.create`, `anthropic.messages.count_tokens`, `anthropic.models.read`, `openai.chat.create`, `openai.responses.create`, `openai.models.read`. The ActionIR carries the model, max tokens, choices, stream, input bytes, provider-side tools and the body hash, never the prompt. Create and count operations have no dedupe key, so identical prompts are independent calls and an SDK's automatic retry is never parked.
4. **Provider-side tools refused unless allowed** (FQ-B, D813, HR-696). A request that asks the provider to run a tool on its own servers (web fetch or search, code execution, remote MCP servers, a container, background mode, or a tool type the package does not list as run by the client) is refused with `MODEL_SERVER_TOOL_NOT_ALLOWED` before the decision, unless an admin allowed that type on the connection. Unknown types count as run by the provider. Policies see `server_tools`.
5. **Limits on model connections only** (D814, HR-692). 16 MiB each way, answers streamed as they arrive, 10 minutes per call, on the edge and the gateway. A stream past a limit or broken is aborted, never passed on as whole, and its outcome is UNKNOWN. Every other connection keeps 64 KiB, buffering and 2 minutes; the M25 campaign route is unchanged.
6. **Secrets in prompts** (Q3, D817, HR-694). Every string of the body and the model id go to the outbound scanner. A held secret is refused, a credential format is held for an approver (`SECRET_IN_PAYLOAD`), and a body the scan cannot finish within its limits is refused.
7. **No capture** (Q4, D820, HR-695). PantherClaw never captures, stores or logs a prompt or a reply on a model connection. Records keep the request's metadata and token counts only.
8. **Tokens reserved by estimate and settled by usage** (Q2, D821, D822, HR-693). A budget rule may carry `max_tokens`, on a grant, a guardrail envelope, or a run (`StartRun.max_tokens`, `pclaw sandbox run --max-tokens`). Before a call the pipeline reserves its max tokens, times its choices, plus a third of its request bytes; a call that would pass a cap is refused with `TOKEN_BUDGET_EXHAUSTED` and agent-safe content only (HR-400). A completed call settles at the usage the provider reported, or at the whole reservation when none was reported. A rejected call releases its reservation. An UNKNOWN outcome keeps it (HR-003).
9. **Usage, outcomes and refusals** (D818, D819). Usage is parsed from the answer or from the stream's events. Refusals take the provider's error shape, so SDKs show them, with the agent-safe explanation.
10. **Estimates, not bills** (Q2, D825, D829, HR-698). An organization may set prices per million tokens on a model connection. On Team, the run inspector and a monthly token report show an estimate from those prices, labelled an estimate. PantherClaw ships no price list.
11. **Held calls through the sandbox** (FQ-C, D817a). The edge gives each request a new action id, so a held model call from a sandboxed agent cannot be resumed after approval, as for every connection today. M29 keeps it stopped and shown.
12. **Zero-token tests** (D826, HR-699). `pantherclaw-sim model` answers both APIs, streamed, with usage numbers and faults by model id. Every test, range scenario and CI job uses it.

**Consequences.**
- The gateway and the sandbox edge see prompts and replies in plaintext on model connections, and token usage reaches the server as the gateway reports it (R-73). The gateway stays in the TCB as for every route (R-01).
- A held call from a sandboxed agent stops: the agent gets a 403 naming `SECRET_IN_PAYLOAD` and the transaction, and the person sees the hold. The person removes the secret from the workspace and the conversation and reruns. A direct client that resends the same action id resumes after approval as today. Resuming through the edge is a follow-up for every connection (FQ-C).
- Spent tokens may pass a cap by what one call's input estimate missed, because the input is estimated from bytes before the call.
- Estimates are not bills. They come from the organization's own prices and the providers' reported counts, and are marked "estimate" wherever they appear.
- A workspace with secrets in it adds approvals, because those secrets reach prompts.
- An SDK sees PantherClaw's refusals as provider errors with a readable message, a code and the transaction.
- Campaigns keep the M25 route; a later change could move them onto model connections.

**Alternatives.**
- A direct passthrough with the agent's own key (Q1 B): faster to build, but the key sits inside the sandbox, nothing is metered, and an injected agent could send the workspace to another account on the same model host.
- Documentation only, no model route (Q1 C).
- Caps in money from a shipped price list (Q2 B): prices go stale and would read as a bill.
- Forwarding the agent's bytes unchanged while deciding on values read from them (FQ-A B), or deciding on the prompt as ActionIR parameters (FQ-A C): the first lets the gateway and the provider read different values; the second does not fit ActionIR's string caps.
- Allowing provider-side tools and leaving them to policy (FQ-B B): a tool the provider runs on its own servers is a route around PantherClaw unless an admin allowed it.
- Following the organization's normal capture setting for model connections (Q4 B).
