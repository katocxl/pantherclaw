### G0 — M23 — Easy to adopt: Hub, CI checks, `pclaw dev` and the managed-settings kit — 2026-10-31

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M23 pull requests and, at the end of the milestone, in the exit status section. The design was written on `main` at ffb6a4e1. M23 builds in parallel with M22 and M24 (W1) and lands in migration order after M22; it may land first if M22 still has no migration (E9). The founder answered the wave 1 rules on 2026-10-31 (H1, H3).

**Purpose:** every customer writes the same policies, detection rules and scenarios from scratch, and a policy change is code with no check in the pull request that makes it. M23 adds a lean Hub of signed PantherClaw content, an offline `pclaw ci check` with a GitHub Action and a GitLab component, a local `pclaw dev`, and a kit that generates admin settings pinning PantherClaw's hook and the allowed MCP servers. Hub cannot reuse package signing: `TargetOf` needs a package, and a Hub document under the packages root would also pass `ImportPackage`. Detections, automation templates, packs and range digests compile in, so install needs a route per kind. No RPC runs offline, `targets.jws` does not exist, NOTICE omits five integrations, and `tools/cicheck` reads only `.github/workflows`.

**Design decisions:**

*S23a — Hub ([ADR-0045](../adr/0045-hub-trust-and-distribution.md))*

1. **D100: the format** (F840, HR-563). Hub is a static directory: `index.jws` plus `items/<sha256>.json`. No archives.
   - `index.jws`: compact JWS, header `typ: "pc-hub-index+jws"`. Payload `spec: "pantherclaw.hub.index/1"`, `version` (uint64, rises), `issued_at`, `expires_at` (at most 180 days), `items[]` of `{name, version, kind, sha256, size, title, summary}`.
   - Kinds are closed: `policy_template`, `detection_rule`, `range_scenario`, `tool_package`, `automation`. No code, no scripts.
   - Item: `spec: "pantherclaw.hub.item/1"`, `name`, `version`, `kind`, `body`. Limits as in D100a.
   - Names match `^pc\.[a-z0-9-]+(\.[a-z0-9-]+)*$`.
   - **D100a: limits and accepted details.** `rpc.MaxRequestBytes` stays 1 MiB, and index plus item travel in one RPC. So an item is at most 384 KiB, a compact index at most 640 KiB, and an index holds at most 1,000 items. Build, CLI and server all enforce these from one constant, and refuse rather than truncate. `Verifier.WithMaxBytes` takes that constant only. Also accepted from S23a:
     - `hub.read` for OrgAdmin, SecurityAdmin, Auditor, PolicyAuthor and AutomationAuthor; `hub.install` the same without Auditor (each kind's own gate still applies);
     - extra codes `HUB_ITEM_INVALID`, `HUB_ENVIRONMENT` and `HUB_INSTALL_BUSY`;
     - PENDING and FAILED install states with a 5-minute stale reclaim;
     - `--scenario-dir`, and the `file_name` pattern `^CX-[0-9]+(-[a-z0-9-]+)?\.yaml$`;
     - CLI rollback keyed by signer;
     - `PANTHERCLAW_HUB_DEV_KEY` for a directory or loopback source only;
     - `keygen --purpose hub|hub-dev`;
     - `hub update` installs nothing.
2. **D101: trust** (F841, HR-560). New `rootkey.PurposeHub = "hub"` and `PurposeDevHub`; `internal/hub/roots.json` (`{"keys":[]}`); `internal/hub/domain/verify.go`. `internal/definitions/trust` does not change. A Hub document never verifies as a package document, and the reverse, tested both ways. The dev key works on loopback only, as `devkey.go` does. Empty roots off loopback give `HUB_NO_ROOT`.
3. **D102: storage** (F842). Layout `internal/hub/{domain,app,adapters/pghub,adapters/hubrpc}`. Migration 00260 `pc.hub_state(org_id PK, index_version, index_digest, updated_at)`. 00261 `pc.hub_installs(id, org_id, name, version, kind, item_sha256, index_version, result_kind, result_ref, installed_by, installed_at, status)`, UNIQUE (org_id, name, version). RLS as in 00188.
4. **D103: API** (F843). `proto/pantherclaw/v1/hub.proto`, `HubService`: `InstallHubItem(index_jws, item, params)`, `ListHubInstalls`, `GetHubState`. Permissions `hub.read` and `hub.install` (person only). Community. `permissions_m23.go`, roles and these protos push first as `(m23-perms)`; the format as `(m23-hub-format)`.
5. **D104: install is inert** (F844, HR-561). The server re-verifies everything; the CLI is transport.
   - `policy_template` → a DRAFT policy version, the same use case as `template apply`;
   - `detection_rule` → `CreateCustomRule` as a draft, keeping its Business gate;
   - `automation` → a `CreateAutomation` draft;
   - `tool_package` → the body holds `package_yaml` and `targets_jws`, through `ImportPackage` unchanged;
   - `range_scenario` → refused `KIND_LOCAL_ONLY`; the CLI writes it locally.
   Nothing is activated, published, enabled or pinned by install. Normal gates then apply.
   - **D104a.** "Pinned" here and in HR-561 means an agent's tool-version pins. A `tool_package` install goes through `ImportPackage` unchanged, so it advances the organization's package anti-rollback state as any import does. The version stays REVIEWED and decides nothing until activated.
6. **D105: errors** (F845, HR-562). `HUB_SIGNATURE`, `HUB_EXPIRED`, `HUB_ROLLBACK` (a lower version, or the same version with another digest), `HUB_DIGEST`, `HUB_NO_ROOT`. Re-installing the same digest is idempotent. The CLI keeps its own rollback state and cache under the `pclaw` config directory.
7. **D106: commands** (F846, F847). `pclaw hub search|show|install|update|status`, flags `--source URL|DIR`, `--set k=v`, `--dry-run`. HTTPS only except loopback; no cross-host redirects. The default source is a constant in one place for the org move. `pclaw-admin hub build --dir hub --out DIR --key F --passphrase-file F --version N --expires-days D`, reusing `loadSigner`.
8. **D107: no outbound call** (F846). The server never fetches the index. "Update available" lives in the CLI for now.
9. **D108: exit.** `feat/m23-exit` holds S23a, S23b, S23c and `docs/m23`. Exit test `TestE2E_M23_HubAndCI`: build with the dev key, install to draft, tampered item refused, rollback refused, `pclaw ci check` reports a widening. `task range` runs: packages and gateway are adjacent.

*S23c — CI and dev*

15. **D120** (F853). `internal/policy/offline`: wraps `scenario.Runner`, `validate.Validator`, `pdomain.Compare` and `engine.Simulate`, with a new file-based definitions and facts source (`--packages DIR`, scenario fixtures). No server, no network.
16. **D121** (F854, F855). `pclaw ci check --policy F [--base F] [--scenarios DIR] [--packages DIR] [--format text|json|markdown] [--fail-on widen|any]`. Exit 0 pass, 1 check failed, 2 usage. Report: validation, scenarios, rule changes by direction, and outcome samples with "N sampled; an empty sample proves nothing".
17. **D122** (F856, HR-565). Markdown output escapes everything from policy files (backticks, `@`, links, HTML), capped at 60 KiB. Policy text cannot mention a person or render markup.
18. **D123** (F857, HR-566). `integrations/github-action/action.yml` composite, with LICENSE and NOTICE, Apache-2.0. Inputs `policy`, `base-ref`, `scenarios`, `packages`, `pclaw-version`, `comment`. Steps pinned by SHA. Checksum-verifies `pclaw`. Needs no secrets. Documented for `pull_request` only, never `pull_request_target`. The comment is skipped on forks; `GITHUB_TOKEN` with `pull-requests: write` only. `tools/cicheck` also checks `integrations/**/action.yml`.
19. **D124** (F858). `integrations/gitlab/templates/pantherclaw-check.yml` CI component, README, LICENSE, Apache-2.0.
20. **D125** (F859). `pclaw dev up|down|status|env` wraps `nodeUp --dev` with the simulators. Loopback only. `pclaw dev env` prints connection settings, never a secret value.

21. **D126 (S23c, high).** `action.yml:97` and `pantherclaw-check.yml:55`: find the archive's checksum with an exact field match, as `install.sh:96` does. Tested with a checksums file that also holds `<archive>.sbom.json`.
22. **D127 (S23c).** `pantherclaw-check.yml:65`: a `base-ref` that cannot be fetched exits 2. Only "the file is absent at a fetched base" counts as no base. No hidden errors.

24. **D129 (S23b)** (F851). `not_found` never reads as fact: the title is "No readable managed settings found", and the detail says that registry, MDM, server-managed and other clients' settings cannot be read here, so the machine may still be managed.
25. **D130 (S23a).** `Begin` hands out a claim token, and `FinishHubInstall` only updates a row holding that token. A reclaimed install whose draft already exists with the same item digest finishes as done; if that cannot be proved, it stays FAILED with a clear error.
26. **D131 (S23c)** (HR-565). All policy-derived text in the Markdown report goes in code spans, sized past any backtick run, so `GH-123`, `#123`, SHAs and mentions never link.
27. **D132 (S23a).** `--scenario-dir` defaults to `./pantherclaw-scenarios`, never `redteam/scenarios`.
28. **D133 (S23c).** Exit 2 posts no comment and leaves the last report alone. A comment failure warns and never fails the check.
29. **D134 (S23c).** `pclaw dev down` stops a process only when the saved PID still matches the started process's identity. Otherwise it reports and leaves it.
30. **D135 (S23a).** A Hub policy install returns and audits `Replaced`, as pack apply does.
