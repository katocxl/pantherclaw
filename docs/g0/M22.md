### G0 — M22 — See it: API gaps, graph evidence, console screens and graph views — 2026-10-31

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M22 pull requests and, at the end of the milestone, in the exit status section. The design was written on `main` at ffb6a4e1. M22, M23 and M24 are one wave built in parallel (W1) and land in migration order: M22 → M23 → M24 (W2). M22 has no migration unless a decision below adds one, so M23 may land first if M22 still has none (E9). The founder decided on 2026-10-31 that all coding comes before live testing and founder steps; the graph default is H5.

**Purpose:** seven milestones (M15–M21) have no console screens: the console pins a core from before M15 and cannot call their APIs. 84 procedures are unknown to it; 73 need screens and 11 are machine-only. A reading of the code also showed that the APIs are not complete, so this is not console work alone: M20 rotation has no RPC at all, graph nodes have no labels, CAUSAL lacks authority, approval, custody and effect edges, and the graph modes other than ACTIVITY lack gaps and some provenance. M22 closes those gaps in the public core, builds every M15–M21 screen, and draws the graph data as views a person can use, each with an equivalent table and links to its evidence.

*Graphs* (TB4, TB7; D11–D17).
- **Information disclosure (T-238):** a label names a record the viewer may not read, or an agent's text renders as markup. Answered by: plain text, at most 200 characters, only from readable names, otherwise empty (HR-550).
- **Repudiation and false assurance (T-239):** a cause is shown with no evidence, or a gap vanishes on collapse. Answered by: `evidence_ref` or a `gap` edge (HR-551); gaps in every mode, never merged (HR-552).

*Rotation* (TB4; D5).
- **Elevation (T-240):** the RPCs skip what the service enforces, or return a secret. Answered by: one-to-one mapping onto the service methods, which keep the step-up and protected change; secrets go through a server page (HR-553).

*Model reads* (TB4; D8).
- **Information disclosure (T-234, existing):** a list or usage read returns stored text. Answered by: no prompts and no responses in either read (HR-554).

**Hardening rules in scope:** the new rules **HR-550..HR-554** added to [HARDENING_RULES](../security/HARDENING_RULES.md) by this brief, plus HR-247, HR-254, HR-257 and HR-258 (permission-safe aggregates and summaries), HR-340 (console text), HR-517..520 (rotation) and HR-541..545 (model drafting).

**Design decisions:**

*S22a — public clean-up*

1. **D1: closed.** #508 already binds TCP and UDP together in `listenDNS` and retries, and no failure of `TestHR121_TheCanaryRecordsMarkersOnEveryPort` appeared in 22 CI runs since. No change.
2. **D2 (own pull request).** RT-027 `split-at-once`: BUDGET_BUSY is retryable. The scenario retries it and still asserts the final invariant (never over budget). The invariant is not loosened.
3. **D3: closed.** #517 fixed the M11 cursor-rewind race on `main`, so it is not redone. `test/e2e` stays one package.
4. **D4 (own pull request).** R-494: read `.gitlab-ci.yml` at the target branch, one GET. R-503: `environmentTerm` covers `production_eu`, `staging_eu`, `dev_eu`, `stage` and `live`. R-507: `Assignments` skips DEPROVISIONING records on a deleted organization; correct the #512 note.

*S22a — API gaps*

5. **D5** (F831, F424, HR-553). New `proto/pantherclaw/v1/credential_rotation.proto`, `CredentialRotationService`: RequestRotation, SealRotationCandidate, TestRotation, ActivateRotation, RollBackRotation, ConfirmRotation, CancelRotation, GetRotation, ListRotations, one to one over `internal/credentials/app/rotation.go`.
   - Permissions, step-up and edition stay as the service enforces them.
   - The secret flow copies `ReplaceExportDestinationCredential` plus `webhttp/export_destinations.go`: an RPC for `pclaw`, a server page for the console.
   - `pclaw credential rotation request|seal|test|activate|rollback|confirm|cancel|get|list`.
6. **D6** (F832). `Agent.scan_state` (message): `missed_scans`, `last_seen_at`, `vanished`, from existing M17 columns.
7. **D7** (F833). `ListTicketRefs` (by case or incident) and `ListTicketSyncEvents` (by configuration, paged) on TicketSyncService, read-only, under the ticket-sync read permission. If no stored sync log exists, the stream stops and asks.
8. **D8** (F834, HR-554). ModelService: `ListModelDrafts` (paged) and `GetModelUsage` (from `pc.model_calls`). No prompts or responses returned. Business, the same gate as drafting.
9. **D9** (F835; own pull request from `main`, first, auto-merge on). `server.ProcedureMap()` plus a command: `go run ./internal/procmap` (not under `tools/`, which is a separate Go module) prints JSON `{"<procedure>":{"permission":"…","class":"…"}}` for every procedure, side maps included. A test checks it against `procedurePermissions` and `procedureClasses`. Today 30 procedures would regenerate without a plan class, because the console generator reads only the literal `procedureClasses` map.
10. **D10: no new RPC, on purpose.** M15b holds stay in Approvals. M17e custom ranges run through `pclaw`; the console shows results. M18e CIDRs stay fixed at creation. The M18a fleet shows current state, no alert history. Secret entry stays on server pages (model key, export destinations, external checks). Graph expand is a new `GetGraph` scoped to a node. Graph export is client CSV from the table.

*S22b — graph evidence ([ADR-0044](../adr/0044-graph-evidence.md))*

11. **D11** (F272, HR-550). `GraphNode.label` (field 3): plain text, at most 200 characters, only from names the viewer may read, otherwise empty. Hidden records stay excluded. Labels are never markup (HR-340).
12. **D12** (F272, HR-551). CAUSAL adds the edge kinds `authorized` (grant → transaction), `approved` (approval → transaction), `custody` (credential lease → dispatch), `effect` (transaction → effect) and `triggered` (transaction → consequence transaction, with predicted, authorized and confirmed kept apart). A new `evidence_ref` on GraphEdge names the receipt. No evidence, no link: a `gap` edge is emitted instead. Observed never reads as possible.
13. **D13** (F289, F293, HR-552). Every mode returns its gaps. Every edge carries source, observed time and freshness (catalog F293, F294, F297). Collapse never merges gaps. The states of catalog F291 are added: Enforced, Allowed, Approval required, Denied, Observed, Possible bypass, Unknown, Stale, and exact partial, pending, conflicting and unverifiable effects.
14. **D14** (F274). CHANGE: a new `GraphEdge.change` enum (ADDED, REMOVED, KEPT) gives before and after for a restriction or incident scope (catalog F276).
15. **D15** (F277). GetCoverageGraph edges gain `reason`, `last_checked_at` and `expires_at` (catalog F278). Nodes gain `effect_group`.
16. **D16** (F284). Timeline lanes carry their events. Timeline events carry `read_class` (catalog F285). Permission rules for hidden children stay.
17. **D17** (F301). Add the staleness metric and the bypass owner. Catalog F302: add missing drills where a source exists; where none does, return "no drill" explicitly.
18. **D18.** All proto changes are additive; `buf breaking` stays clean. Proto and generated code push first as `(m22-graph-proto)`.
19. **D19.** `feat/m22-exit` holds S22a, S22b and `docs/m22`. Exit test `TestE2E_M22_GraphData`, plus rotation and the D6–D8 reads.
