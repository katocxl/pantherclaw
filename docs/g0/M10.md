### G0 — M10 — Detect, investigate, respond — 2026-10-15

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M10 pull requests and, at the end of the milestone, in an exit status section. It builds on `main` at 8ef2fbcb (M1–M9, M12, the v0.1.0 preview and M11.1 complete; the highest migration is 00113 and 00114–00119 are M11.1's spares). The founder answered four open decisions (F1–F4) on 2026-10-15 before the brief was written, the recommended option each time; they are recorded at the end as answered. Every other choice is a design decision made by the coordinator, for the founder's confirmation on this pull request.

**Purpose:** PantherClaw decides and records every agent action, but nothing reads those records for attacks. A tool description that starts giving orders, an agent that tries to grant itself authority, a burst of probing denials or a sensitive read followed by a write to a public destination are all in the evidence ledger and nobody is told. When someone does notice, there is no place to investigate, the only response is the org-wide kill switch or a handful of single-record actions, and nobody can say what an agent could still reach. M10 adds that loop. Detection rules run over the evidence ledger, off the decision path, and raise alerts that are grouped into incidents. Cases collect facts, hypotheses and open questions with evidence. Containment controls narrower than the kill switch are enforced in the decision path, each confirmed per path, and lifted only through restoration. Breach radius shows observed, effective and credential/bypass reach separately. Operators get a work queue, a live stream and permission-safe search; findings and alerts go out as OCSF 1.9; and the customer's IdP can send Shared Signals (CAEP/RISC) that open cases or, with an opt-in playbook, contain the person. In product terms this is Reflex ([PRODUCT.md](../PRODUCT.md)).

*The inbound Shared Signals endpoint* (`POST /v1/ssf/{org}/{transmitter}`, TB8, D37). It is the first unauthenticated-by-session inbound endpoint that can change authority (through the playbook).
- **Who can reach it:** anyone on the network. The only credential is the SET's signature.
- **Spoofing:** a forged SET; a SET signed by a key the attacker supplies (`jku`, `x5u`, `jwk` headers); a SET from another transmitter's issuer; a SET meant for another audience; an `alg: none` or HMAC SET signed with a public key. Answered by: only ACTIVE transmitters configured by a person with a step-up; keys only from the JWKS pinned to the issuer's host, fetched through the egress client; an RS256/ES256 allow-list; key headers refused; `iss` and `aud` checked (HR-261, T-113).
- **Tampering and replay:** a captured SET sent again, later, or to another org's path. Answered by: `iat` within ±5 minutes; `jti` unique per transmitter for 7 days; the org and transmitter from the path must match the configuration that verified the signature.
- **Repudiation:** every received SET is recorded with its `jti`, issuer, event type, verification result and outcome.
- **Information disclosure:** error bodies are the RFC 8935 codes only, never whether a subject matched a person; no match records the event and opens nothing.
- **Denial of service:** bodies ≤ 64 KiB, a rate limit per transmitter, JWKS refetch on an unknown kid at most once a minute, exactly one event per SET.
- **Elevation:** a SET that contains a person. By default a SET only opens a case; containment needs the identity playbook and a subject matched by `iss_sub` (an email match only opens a case, D46), which is off by default and enabled only by two distinct people with distinct security keys (HR-262). Its actions are ordinary containment controls, reversible through restoration (R-30).

*The outbound export* (OCSF batches to SIEM destinations, TB8, D35, D36).
- **Who controls it:** an admin with `siem.manage` creates a destination; a person activates it with a WebAuthn step-up.
- **SSRF:** a destination pointed at loopback, a private range, a cloud metadata host or a host that resolves there later. Answered by: HTTPS only; the URL checked at creation (`CheckWebhookURL`) and enforced at dial time by the egress client; private and loopback only when the destination is marked internal (which also needs the step-up); metadata hosts always refused (HR-259, T-114).
- **Oversharing:** a destination that receives audit or decision data it was not meant to see. Answered by: per-destination data classes; bodies carry ids, subjects, decisions and reasons, never payloads or secrets (D6).
- **Spoofing and tampering towards the receiver:** Standard Webhooks signatures with a per-destination secret and a 24-hour rotation overlap; `webhook-id` is the batch id.
- **Loss and duplication:** a per-destination cursor advanced by compare-and-set that never skips (D46); at-least-once delivery with stable `metadata.uid` for dedupe (R-31); delivery health separates configured from delivery-confirmed, and failing delivery raises an owned failure (HR-260).

**Security constraints and design decisions:**

*Core (W1)*
9. **Detection rules (D9).** YAML with `id` (built-ins `pc.<area>.<name>`, custom `org.<slug>`), `version`, `title`, `description`, `severity`, `attention`, `basis`, `atlas[]` and `owasp[]` (closed lists embedded: ATLAS `AML.T####(.###)`, OWASP agentic `ASI01`..`ASI10`), `edition` (community | business), `on[]` (event kinds, exact or `prefix.*`) and `match` (a CEL boolean over `event`). Optional detectors: `window{duration ≤ 24h, group_by[], count, distinct?}`, `first_seen{keys[], horizon ≤ 90d}`, `sequence{steps[{on, match}] (2–4 steps), within ≤ 24h, group_by[]}`. Also `group` (run | agent | principal | grant | target | connection) and `tests[]` (event fixtures with `fires: bool`). The CEL environment is `celenv.New(DefaultLimits, schema)` with one variable, `event` (the D2 fields).
10. **The engine (D10, HR-240).** A per-org River job reads `feed.After(cursor)` in batches of 500, evaluates the rules, updates counters, seen-sets and sequences, raises signals through `Raiser` in the same transaction, then advances `pc.detection_cursors(org_id, seq)` by compare-and-set (`WHERE seq = $old`), so each feed entry is evaluated once per org. It is never on the decision path. Cardinality caps: at most 10 000 group keys per rule per window and 100 000 seen keys per rule; on overflow events count into an `__overflow__` key and one `FailureSink` report goes out per rule per day. Evaluation errors count per rule; 10 in a row disable the rule with a failure report. The dispatcher runs every 5 seconds.
11. **Built-in pack v1 (D11).** Embedded `internal/detection/pack/builtin/*.yaml` with a `manifest.json` holding each file's SHA-256 and the pack version.

12. **Pack integrity (D12, HR-241, F4).** The built-in pack ships inside the release-signed binary. At startup `pack.Load` checks every file against `manifest.json` and the manifest's digest against the generated constant `PackDigest`; `task check` fails when the constant is stale (a test regenerates and compares). On a mismatch detections stay off and an owned failure is raised; the server still serves decisions, because detection is never on the decision path. Every alert records `pack_version` and `rule_digest`. Custom rule versions are recorded with their content digest in the ledger (`audit.detection.rule_published`), and the engine refuses to run a custom rule whose stored content digest differs from the ledger-recorded one.

21. **Containment controls (D21, HR-248; F547, F552, F561).** `pc.containment_controls`: `scope_type` ∈ agent | run | grant (with dependants via `grant_lineage`) | connection | resource (a target pattern) | principal (a user); `control` ∈ DENY_ALL | HOLD_WRITES | DENY_OPERATION(op); `reason`; `case_id` or `incident_id`; `created_by`; optional `expires_at`; `lifted_at`. An agent with no coverage record gets one UNKNOWN route path, which is material. In-flight dispatches are not material for a containment (they are listed in `historical_open`) and are material for a termination.

**Residual risks** (added to THREAT_MODEL §8 by this brief):
- **R-28:** detections are heuristics, so there are false negatives: an attack that matches no rule raises nothing. Compensating controls: detection is a second line behind grants, policy and containment, which decide every action; the built-in pack maps to ATLAS and OWASP agentic; custom rules (Business); the adversarial range runs the attack catalogue.
- **R-29:** credential reach is only as complete as credential metadata: a credential whose scopes PantherClaw cannot read understates the credential/bypass view. Compensating controls: unknown scope is UNCERTAIN, never absent (HR-253); credential-overreach findings; custody of credentials in the gateway.
- **R-30:** a compromised IdP can trigger cases or, with the playbook on, containment. Compensating controls: containment is reversible through restoration (HR-250); the playbook is off by default and enabled only by two people with two keys (HR-262); every SET is recorded with its issuer and `jti`.
- **R-31:** export and stream are at-least-once: a retry or resume can deliver an event twice. Compensating controls: consumers dedupe by id (`metadata.uid`, the SSE `id`); the cursors are compare-and-set, so nothing is skipped.
- **R-32:** HR-079's entropy limit catches raw binary only; base64, hex and prose pass it by design, so encoded exfiltration within a parameter's byte cap is not refused. Compensating controls: the byte cap per parameter per action is the control; the `sequence.read_then_disclose` and `budget.splitting` detections (D73).
