### G0 — M21 — Branching automations, recommendations, outcome metrics and model drafting — 2026-10-29

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M21 pull requests and, at the end of the milestone, in the exit status section. The design was written on `main` at 5225b371 from the M21 code map. M21 lands last of M15–M20 in migration-number order, so its migrations start at 00246. The founder answered both M21 decisions (G16, G17) on 2026-10-29 with the recommended option; the coordinator's design decisions are D300–D305.

**Purpose:** M11 delivered governed automations whose steps run in a fixed line: a step can be skipped by a guard, but a definition cannot say "if the change is to production, wait for approval, otherwise notify". Customers who connect PantherClaw are told what is protected, but not which identity, approval or incident connections would close their remaining gaps, nor how long it takes to get to protected work, to understand a decision or to contain an incident. Plain-language search is deliberately rule-based, and drafting a policy or automation from a sentence is not possible at all. M21 adds explicit branches to automations, dependency-led recommendations, outcome metrics that never pass raw volume off as value, and optional, customer-keyed model drafting whose output is only ever a draft or a shown query.

**Scope (planned, D300):**
- **21a Branching engine** (F678). A v2 definition format with `branch`, `switch` and `join` nodes, terminal outcomes per path, a graph validator (reachability, cycles, per-path authority and irreversible waits), node-pointer run state, and simulation, replay and inspection over paths. v1 definitions and running v1 executions are unchanged.
- **21b Recommendations** (F343). Computed on read from discoveries, coverage, onboarding and connections: which identity, classification, approval, incident or export integration would close a discovered need, what each enables and what stays unsupported.
- **21c Outcome metrics** (F774). Six duration and assurance measures (M1–M6 below), each with its data source and its "not measured" cases, rolled up nightly; DRAFT definitions that the founder signs off (G17).
- **21d Model drafting** (F181, F304 natural-language part). An optional model-provider port (first adapter: the Anthropic Messages API with the customer's own key) that turns text into a structured search query, policy draft or automation draft. Off by default, Business edition; nothing it returns runs.
- **21e** this brief and the exit end-to-end test.

Editions: branching follows automations (Team); recommendations are Team; outcome metrics are Business (`OutcomeMetrics()`); model drafting is Business (`ModelDrafting()`, founder decision G16).

*Branching* (TB4; D301).
- **Elevation (T-230):** an author hides an effectful or irreversible step on a branch the whole-definition checks treat differently, or builds a loop. Answered by: no cycles and every node reachable (HR-531); authority and irreversible waits checked per path, and the whole-definition ceiling check kept, the stricter applying (HR-532).
- **Tampering (T-231):** the v2 format or migration re-points a running execution, changes how a v1 definition runs, or compensates steps that never ran. Answered by: v1 unchanged (HR-530); pinned version and state never re-pointed (HR-533); only the taken path compensated (HR-534).

*Recommendations* (TB4, TB7; D302).
- **Information disclosure (T-232):** a recommendation reveals discoveries, agents or connections outside the viewer's scope. Answered by: viewer-scoped (HR-536); recommendations never act (HR-535).

*Outcome metrics* (TB4; D303).
- **Repudiation and misleading claims (T-233):** gaps shown as zero, requested containment counted as confirmed, volume dressed up as value, or a metric shown without its scope. Answered by: HR-537..540.

*Model drafting* (TB13; D304).
- **Information disclosure (T-234):** records, payloads, evidence or untrusted text reach the customer's model vendor, or the key leaks. Answered by: off by default and opt-in (HR-541); only the task kind, the user's own text, the target schema and a permission-scoped name catalogue are sent (HR-542); every call audited and the key write-only (HR-545).
- **Tampering and elevation (T-235):** model output, or instructions injected into it, executes, publishes, enables or runs a query. Answered by: only strictly parsed structured output is accepted (HR-543); it is a draft or a shown query and never executes (HR-544).

**Hardening rules in scope:** the new rules **HR-530..HR-545** added to [HARDENING_RULES](../security/HARDENING_RULES.md) by this brief, plus HR-070..077 (egress), HR-230 and HR-231 (the publication gate), HR-258 (operations summaries), HR-280 (automation retries and stable step identity) and HR-295 (search).

**Design decisions:**

*S21a — branching (F678)*

1. **D301: the v2 format** (HR-530).
   - `apiVersion: automations.pantherclaw.dev/v2` with `nodes:`. A v1 definition parses unchanged and is lifted in memory to a linear graph; v1 parsing is frozen, with golden tests, because the engine re-parses stored v1 JSON for running executions.
   - Node kinds: `branch` (if/else on one guard), `switch` (ordered cases and a required default) and `join` (`ALL` or `ANY` of named incoming nodes). Paths are mutually exclusive; there is no parallel execution.
   - Guards use the existing `when` expression grammar.
   - Each terminal node declares an `outcome` and its `finish_when`; the execution's final state comes from the terminal reached, still checked against evidence.
2. **D301: validator errors** (HR-531, HR-532).
   - `UNREACHABLE_NODE`; `PATH_NOT_TERMINATED`; `CYCLE`; `SWITCH_NO_DEFAULT`; `JOIN_INVALID`;
   - `NOT_ON_ALL_PATHS`: a reference or template must name a node that precedes its user on every path (replaces today's "earlier step" check);
   - the per-path ceiling check and `IRREVERSIBLE_UNWAITED_ON_PATH` (each path's irreversible operation needs a `wait_effect` on that same path);
   - bounds: at most 40 nodes, 64 paths and depth 20.
   - The whole-definition ceiling check stays as well; the stricter of the two applies.
3. **D301: run state** (HR-530, HR-533).
   - Migration 00246 adds `current_node` and `path` to `pc.automation_executions` and `node_id` and `visit` to `pc.automation_step_attempts`, with a new unique key on node id, and backfills `node_id = step_id` for existing rows without touching identity columns. Migration 00247 updates the guard trigger.
   - v1 executions keep the step-index path. No execution changes version.
   - Tested against a database holding WAITING v1 executions.
4. **D301: compensation, simulation, graph** (HR-534).
   - Compensation covers only the effectful nodes on the taken path, in reverse order.
   - Simulation and replay evaluate guards on the trigger data; a guard that cannot be evaluated is `UNEVALUABLE`, and both branches are shown.
   - The graph proto gains edge `label` and `guard` and the edge type `BRANCH`.

*S21b — recommendations (F343)*

5. **D302** (HR-535, HR-536).
   - Computed on read from discoveries, coverage, onboarding and connections; dismissals in `pc.recommendation_dismissals` (00248).
   - A closed Go catalogue: each entry maps a signal to a recommendation with `enables[]`, `still_unsupported[]` and an evidence link. Targets are the integrations that exist after M20; anything else is stated as unsupported.
   - Team edition, readable with `posture.read`, viewer-scoped. A recommendation never changes anything.

*S21c — outcome metrics (F774; founder decision G17)*

6. **D303: common rules** (HR-537..540).
   - Each metric is a distribution over a window of at most 30 days: median, p90, the count of measured cases, and the count of cases that could not be measured with their reasons.
   - A window with no measurable case is `NOT_COLLECTED`, never 0. Windows before collection started are `NOT_COLLECTED` (no backfill).
   - Every result is stamped with its scope and as-of time, and states which records it could not see.
   - A nightly River rollup writes `pc.outcome_metric_samples`. Business edition through `OutcomeMetrics()`.
   - New timestamps: agent milestones, explanation first views, approval `first_decided_at`, case and incident `contained_at`, an action-to-case link, rollout stage events, and `execution_id` on actions an automation caused.
7. **D303: the six definitions.** Each is **DRAFT: founder sign-off required (G17)** before M21's exit pull request lands.

   **M1 — Time to protected work.** DRAFT: founder sign-off required (G17).
   - *Measures:* per agent, from its first enrolment (`agent_changes` `instance.enrolled` or `instance.admitted`) to its first non-simulated `pc.transactions` row decided in enforce mode (joined through `runs.agent_id`).
   - *Data source:* `pc.agent_changes`, `pc.transactions` (`mode`, simulated flag), `pc.runs`; new `pc.agent_milestones (agent_id, kind, at)`, written once.
   - *Not collected:* agents enrolled before tracking started; agents with no enforced decision yet (counted as open, with their age); routes never ENFORCED in the window.

   **M2 — Time to explanation.** DRAFT: founder sign-off required (G17).
   - *Measures:* agent side, the share of non-ALLOW decisions delivered with their agent-safe explanation in the same response (reported as a share, not a time, since delivery is inline); people side, from a non-ALLOW decision to the first read of its evidence by a person with access (`GetTransactionEvidence`).
   - *Data source:* `pc.transactions`, `pc.decision_receipts`; new explanation first-view records per transaction.
   - *Not collected:* no read audit existed before M21; decisions nobody opened (shown as unread, with their age); refusals that never reached a person.

   **M3 — Time to containment.** DRAFT: founder sign-off required (G17).
   - *Measures:* from the earliest of alert, incident or case creation to the first CONFIRMED containment for it (`response_actions.settled_at` with status CONFIRMED, or a case entry to CONTAINED). Requested-to-confirmed is reported separately.
   - *Data source:* `pc.alerts`, `pc.incidents`, `pc.incident_events`, `pc.cases`, `pc.case_entries`, `pc.response_actions`; new `contained_at` on cases and incidents and a case link on manual revokes.
   - *Not collected:* grant revokes or suspensions not linked to a case; kill-switch episodes before the history table; UNSUPPORTED or FAILED actions (listed, never counted as contained).

   **M4 — Friction.** DRAFT: founder sign-off required (G17).
   - *Measures:* (i) approval wait, from `approval_requests.created_at` to the first decision, p50 and p90; (ii) hold rate, held decisions over decisions in enforce mode; (iii) override rate, a DENY followed within 7 days by an exception for the same agent and rule.
   - *Data source:* `pc.approval_requests`, `pc.approval_responses`, `pc.transactions`, `pc.policy_exceptions`; new `first_decided_at` on approval requests.
   - *Not collected:* re-queued approvals before M21 (their first approval time was overwritten); retries (there is no retry chain between transactions); an agent giving up is unknowable.

   **M5 — Change assurance.** DRAFT: founder sign-off required (G17).
   - *Measures:* the share of policy and automation versions published in the window that had validation, a scenario test, a simulation and a staged rollout before publication, each check shown separately and never as one score; plus rollout targets that reached FAILED.
   - *Data source:* `pc.policy_change_requests`, `pc.policy_validations`, `pc.policy_test_runs`, `pc.policy_simulations`, `pc.policy_rollouts`, `pc.policy_rollout_targets`, `pc.automation_versions`; new `pc.policy_rollout_stage_events`.
   - *Not collected:* emergency and break-glass changes (listed separately); rollout stage history before M21; downstream verification where it is not configured.

   **M6 — Automation usefulness.** DRAFT: founder sign-off required (G17).
   - *Measures:* per automation, live executions completed with evidence, partial, failed, needing reconciliation and cancelled (cancelled no longer folded into another bucket); interventions; the compensation rate; the share reverted by a person. No time saved is claimed.
   - *Data source:* `pc.automation_executions`, `pc.automation_step_attempts`, the existing `automation.outcomes` metric; new `execution_id` on response and restoration actions an automation caused.
   - *Not collected:* reverts not linked to an execution; SHADOW and TEST runs (excluded).

*S21d — model drafting (F181, F304; founder decision G16)*

8. **D304: the port** (HR-541, HR-542).
   - `internal/model/ports.Provider.Draft`. The first adapter is the Anthropic Messages API with the customer's own key; the model id is configurable per organization, default `claude-opus-5-5`.
   - A request carries a fixed task kind, the user's text (at most 2,000 characters), the target JSON schema and a permission-scoped catalogue of names. It carries no records, payloads, evidence or untrusted text. No tool use; the output schema is closed.
   - Separate RPCs: `DraftQuery`, `DraftPolicy`, `DraftAutomation`. Business edition through `ModelDrafting()`, off by default, enabled per organization.
9. **D304: egress and custody** (HR-545).
   - The provider host is fixed per adapter and called through `httpx.NewEgressClient`: HTTPS on 443, a 30-second timeout, a 64 KiB response cap, and per-organization rate and daily budget caps.
   - Every call is audited without its text. An organization off switch and a platform kill switch; self-hosted deployments keep it off unless the environment allows it.
   - The key is envelope-encrypted per organization (purpose `model_secrets`) and write-only.
10. **D304: only the reviewed structured form executes** (HR-543, HR-544).
    - Output is parsed strictly into a search query or built-in, a policy bundle, or an automation definition through the automation parser (v2 once `(m21-v2format)` lands). Anything else is refused.
    - A search draft is re-resolved through the viewer-scoped interpretation checks, shown with its generated query, and never run; `Ask` stays deterministic.
    - Policy and automation drafts land as DRAFT only (`origin=model`) and go through the M11.1 gate like any draft.
    - Vague terms come back as `ambiguities[]`, each with a proposed threshold that the reviewer confirms; otherwise the draft is refused.
