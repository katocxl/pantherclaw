### G0 — M32 — Kubernetes and edge enforcement: admission, the edge as a native sidecar, gateway enrolment from a projected token and kube closures — 2026-11-05

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M32 branches and, at the end of the milestone, in an exit status section. M32 is code-only like M30 and M31: every stream codes on pushed branches first, and testing (the HR and T rows below) comes later.

**Purpose:** an agent running as a pod in a customer's own cluster gets what the Docker sandbox gives a laptop: one route out, through the edge to the gateway, and evidence that the route is the only one. An admission webhook refuses a pod without the edge, the NetworkPolicy lets the pod reach only the gateway, the gateway enrols from its own projected token, and a daily probe run records a kube closure that coverage reads like a sandbox closure ([ADR-0059](../adr/0059-kubernetes-containment.md)).

**Founder decisions (2026-11-05, all recommended):** FQ32-1 the admission webhook fails closed (`failurePolicy: Fail`); FQ32-2 the edge is a native sidecar in each agent pod; FQ32-3 agent pods get no DNS; FQ32-4 self-hosted clusters only in M32 (hosted clusters later, relayed through the customer's gateway).

**Coordinator decisions:**
- **D964 Labels.** A namespace is protected when it has `pantherclaw.dev/protect: "enforce"` and `pantherclaw.dev/org: "<org uuid>"`; every pod in it is an agent pod. The edge container is `pantherclaw-edge`, it listens on port 3128, its CA is in the emptyDir `/pc-edge`; gateway tokens have audience `pantherclaw-gateway:<org>`, agent tokens `pantherclaw:<org>`.
- **D965 Agent NetworkPolicy.** Egress only to the gateway pods on the gateway API port, no DNS, no ingress unless `ingressFrom` is set; the edge reaches the gateway by a fixed Service address.
- **D966 Edge `kubernetes` mode.** Loopback only (`127.0.0.1:3128`); a workload key in memory only, enrolled by kubernetes attestation from the projected token and renewed by re-attesting; one run per pod, named after it; the per-session CA's certificate only written to `/pc-edge/ca.crt`; a loopback-only `POST /__pc/report` that signs a probe report with the pod's key and submits it.
- **D967 Admission webhook.** Its own TLS listener, off by default; `POST /admission/v1/{cluster}/{org}/{secret}`, any mismatch 404; pod CREATE and ephemeral containers (always denied). A pod needs an ACTIVE kubernetes issuer entry for its service account, one app container (pinned when the entry pins), one native `pantherclaw-edge` sidecar with an allowed digest, no host namespaces, privileged containers or hostPath, and its projected token only in the edge. Any internal error denies (`K8S_UNAVAILABLE`); denies are audited `kubernetes.admission_denied` at most once a minute per cluster, namespace and code.
- **D968 Gateway enrolment from a projected token.** A gateway's kubernetes binding (cluster, namespace, service account, its UID, optional digests) is set or cleared with `gateways.manage` and audited; enrolment by TokenReview against the bound cluster issues the same 24 h certificate.
- **D969 Helm.** The server's cluster config and reviewer binding, an optional gateway Deployment, the admission listener, and per agent namespace a NetworkPolicy, a reviewer Role, a ValidatingWebhookConfiguration (`failurePolicy: Fail`, `sideEffects: None`, 5 s) and a daily probe CronJob; chart defaults stay hardened (HR-398).
- **D969a Webhook secret.** The chart generates the webhook path secret when none is given; a GitOps re-render that does not keep the Secret generates a new one, which rotates it (the server re-reads the file every minute).
- **D970 Kube closures.** The probe's `kubernetes` profile tries the API server, the kubelet, the node, the metadata service, cluster and external DNS, a direct HTTPS address, another Service and pod, and IPv6, then the edge's controls, and posts its report to the edge. The server accepts it only from an L2 instance enrolled by kubernetes attestation whose binding namespace is the report's, with edge and probe digests from the admission lists and a fresh nonce; it adds `admission_enforced` and `netpol_egress_gateway_only` itself, and records a closure per mapped connection under the `ContainmentKubernetes` profile, expiring after 24 h. A control CronJob in the release namespace runs the positive twins. Threat map: `prevent.kubernetes_closure` (T1552.005, T1613) and `prevent.kubernetes_admission` (T1610).
- **D971 Enrolment.** Pods enrol with `enrolled_via = attestation`; a kube closure is signed by the pod's attested key, not a host (R-17).
- **D972 Streams and phases** as in the table above; code-only.
- **D973 Pod runs.** A pod's run starts under its issuer entry's approved run grant: `KubernetesService.StartPodRun` refuses an instance whose entry has no run grant (`K8S_NO_RUN_GRANT`) or a pod name other than the attested one, and the run's launcher is the issuer entry.

**Out of scope:** hosted clusters (FQ32-4), DNS for agent pods, a CNI of PantherClaw's own, and any live cluster run (testing and founder steps).

**Security constraints.** Fail closed everywhere: the webhook denies on error, the NetworkPolicy allows only the gateway, and a closure closes nothing without its controls and both server checks. The pod's workload key and the edge's CA key never leave memory. Wording follows HR-681's list in code, CLI, MCP and docs.
