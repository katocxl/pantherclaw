### G0 — M26 — Enterprise identity: IdP access, MCP client authorization, SCIM, SAML and SaaS agent discovery — 2026-11-01

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M26 pull requests and, at the end of the milestone, in the exit status section. The design was written on `main` at baaa118d and the brief on 72993c28. M25, M26 and M27 build in parallel as wave 2 (W1) and land in migration order (W2). The founder answered the wave 2 rules on 2026-10-31 (H4) and the open questions on 2026-11-01 (H7, H8). The rows were rewritten from the streams' final text on 2026-11-03 (D561); the streams' numbers win over the first draft (D514).

**Purpose:** enterprises want agent access granted in their identity provider and enforced per task by PantherClaw. Standard MCP clients expect the MCP 2026-07-28 authorization flow. IT wants SCIM and SAML before it signs. And most enterprise agents are built in SaaS tools that PantherClaw does not mediate, so they do not appear at all. M26 makes PantherClaw the per-task layer behind the customer's IdP, adds an opt-in route for standard MCP clients, adds SCIM and SAML, and lists agents from Copilot Studio and ChatGPT Enterprise. A reading of the code found: nothing tagged M26 exists; `oauthhttp.HandleGrant` is the jwt-bearer entry; ID-JAG is still an IETF draft, so it sits behind an adapter; organization identity providers exist only for sign-in (ADR-0039); no real captures of the SaaS sources exist yet.

**Scope:**
- **26a IdP access** (F910–F913; D400–D403, D408). Cross App Access assertions behind an adapter, per-organization issuers and client bindings, an opt-in MCP authorization route with allow-listed clients, and a simulated IdP.
- **26b Provisioning** (F918–F923; D405, D406, D409). SCIM and SAML: tables and ports in public core, code in a clean private package.
- **26c SaaS discovery** (F924–F929; D407). Copilot Studio and ChatGPT Enterprise, metadata only, tested on synthetic fixtures.

Editions (H4, H7, Wave 2 plan): N8 is Team on its own entitlement, `IdpAccess()`, checked when a change is filed and when it applies, never on the token path. SCIM and SAML are Enterprise, `SCIM()` and `SAML()`, to add; reads, removals, deprovisioning, disabling and sign-in on an ACTIVE connection work in every edition. SaaS discovery is Business, `SaaSDiscovery()`.

**Out of scope:**
- an assertion creating or widening a grant (H8, HR-146);
- a service that issues downstream tokens: ADR-0018 rejected one, and [ADR-0048](../adr/0048-idp-assertions-and-mcp-client-authorization.md) says why this is not one;
- Entra conditional-access facts (D403);
- a real tenant check: it stays pending (D403, F801);
- a role that binds roles, or Emergency Responder, set from a group (D406, D409);
- just-in-time users from SAML, and IdP-initiated SAML (D409);
- automatic revocation of a deprovisioned person's API keys (D409);
- conversations, prompts or instructions from any SaaS source (H3, F789);
- control over SaaS agents: they stay observe-only with no key path (D407);
- a new repository (H7).

*IdP access* (TB1, TB8).
- **Spoofing (T-266):** a forged, replayed, expired or misaddressed assertion, or a compromised IdP. Answered by: use or narrow an existing grant (HR-620), several grants fail closed (HR-621), strict ID-JAG checks (HR-622).
- **Elevation (T-267):** token confusion between bearer and workload tokens, or a bearer token passing an attestation rule. Answered by: a keyless `mcp_client` instance and confirmed client documents (HR-625), bearer mode from the token type alone (HR-626), level 0 (HR-627).
- **Spoofing (T-268):** a client that isn't allow-listed, or one impersonating an enrolled agent. Answered by: two-person changes (HR-623), `private_key_jwt` from an admitted instance (HR-624).
- **Tampering (T-269):** stolen codes or refresh tokens, a redirect the client never registered, mix-up. Answered by: the code flow's checks, rotation, and reuse ending the run (HR-628).

*Provisioning* (TB8, TB12).
- **Elevation (T-270):** a stolen SCIM token or a hostile IdP admin grants administration, removes the last admin, or undoes a person's disable. Answered by: tokens bound and activated by a second person (HR-629), no admin roles from groups (HR-630), two-person mappings (HR-631), deprovisioning rules (HR-632).
- **Spoofing (T-271):** a forged, wrapped, replayed or misdirected SAML assertion. Answered by: connections as organization identity providers (HR-633), strict SP-initiated sign-in (HR-634).

*SaaS discovery* (TB8).
- **Elevation (T-272):** a hostile tenant uses discovery to gain authority or mislead people. Answered by: metadata only (HR-635), closed kinds (HR-636), inert text (HR-638), an owner and nothing else (HR-639).
- **Repudiation (T-273):** someone other than the lease holder reports a scan, or an unreported lease reads as a clean tenant. Answered by: lease checks and not scanned, never none found (HR-637).

**Migrations.** `00290`–`00294` as the registry says. **Design decisions:**

*S26a — IdP access ([ADR-0048](../adr/0048-idp-assertions-and-mcp-client-authorization.md))*

1. **D400** (F910, HR-620, H8). `internal/idaccess/{domain,app,ports}`; port `AssertionVerifier`, adapter `adapters/idjag` naming the draft revision. It enters through jwt-bearer. `iss+sub` maps to `pc.users`; `client_id` maps to an enrolled agent by a pinned binding (HR-140). Run principal source `id_jag`. No existing grant: refused `NO_GRANT`.
2. **D401** (F911, HR-623). `pc.org_assertion_issuers`, a two-person protected change, HTTPS discovery through the egress guard, pinned audience. `IdpAccess()` Team. ADR-0048 amends ADR-0039 point 2 and explains why this isn't ADR-0018's rejected token-exchange service.
3. **D402** (F912, F913, HR-625..627, H8). Gateway face `internal/gateway/mcpauth`, off by default per organization. MCP 2026-07-28: RFC 9728 metadata, issuer check, RFC 8707 audience, Client ID Metadata Documents. Token `pap-mcp+jwt`, 5 minutes, one gateway server, re-verified by the Authority (HR-021). PAP/1 routes are unchanged.
4. **D403** (F910). `internal/sim/okta`, with the SIMULATED mark. The real tenant check stays pending (F801). Entra conditional-access facts are out.
5. **D408** (F910–F913, HR-620..628). The spec reading (ID-JAG draft-06, the MCP pages, the client metadata draft) is recorded in S26a's hand-back. Bearer clients act as a keyless `mcp_client` instance at level 0. jwt-bearer uses `private_key_jwt`; no key in a client document is trusted. Scope narrows on the run with no grant row; several grants fail closed. The code flow needs PKCE S256 and consent; refresh tokens rotate and die with the run. Adding is a held CUSTODY change; removing is immediate. Bearer mode comes from the token type alone.
6. **D540, D542** (F913, HR-622, HR-625, HR-628). An allow-list entry keeps its confirmed client document; a redirect only a changed document lists is refused `CLIENT_DOCUMENT_CHANGED`, and `RefreshMcpClientDocument` files the new document as a new two-person change. Replay records commit before any refusal. A reused code or refresh token ends the run and its descendants.
7. **D559, D560** (HR-622, HR-625). An untenanted issuer entry is never used while an entry of that issuer pins a tenant, in any state. Every refused attempt on a changed document is audited, and admins are told once per changed document. The `00291` Down never deletes evidence.

*S26b — provisioning*

8. **D405, D409** (F918–F923, HR-629, HR-633, HR-634, H7). Core tables and ports in public core; the private package and `pantherclaw-server-ee` with no billing or console. Routes `/v1/ext/scim/v2/*` and `/app/ext/saml/*` (HR-341 unchanged). The SAML library is gosaml2 with goxmldsig, behind a strict wrapper, in the private repository only; the assertion itself must be signed. SCIM tokens start PENDING and inert until a second person activates them. No just-in-time users.
9. **D406, D409** (F920, HR-630..632). Roles that bind roles and Emergency Responder can't be mapped; a test walks every role. Deprovisioning ends sessions; keys the person made stay and raise an owned finding. Mapping add and remove are held. `SCIM()`, `SAML()` Enterprise.
10. **D527, D528, D544** (HR-629, HR-632). Edition checks read the org's plan inside its transaction. Removals apply in every edition. Each extension set's audit recorder is limited to its own kind prefixes.

*S26c — SaaS discovery*

11. **D407, D534, D535** (F924–F929, HR-635..639). `internal/saasdiscovery`, sources `copilot_studio` and `chatgpt_enterprise`, with packages `pc-copilot-studio` and `pc-chatgpt-enterprise`, whose API shapes stay unconfirmed until a real tenant check. Pure parsers, `pclaw discover import`, and a collector under a `saas_scan` lease, tested on simulators. Metadata only. Unread is per record. Found agents land DISCOVERED and observe-only, marked `external`; naming an owner sets the owner only. A queue source. `SaaSDiscovery()` Business.
