### G0 — M29 — Model connections and token budgets: the agent reaches its model through the gateway, caps in tokens, a fake model for zero-token tests — 2026-11-04

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M29 pull requests and, at the end of the milestone, in the exit status section. The design was written from a reading of `main` at 44f281bb and the M28 exit. The founder approved the plan as planned on 2026-11-04 (Q1–Q5) and answered three further questions the same day (FQ-A, FQ-B, FQ-C). The streams build in parallel and land as one exit pull request.

**Purpose:** a coding agent run in `pclaw sandbox run` could not reach its model, and nothing measured or capped the tokens agents spend. A reading of the code found five blocks: the edge refuses every host without a mapped connection and no connection package exists for a model provider; the edge strips the agent's key; `pclaw sandbox run` has no `--env`; the edge and the gateway's HTTP face cap bodies at 64 KiB; and neither streams, with a 2-minute timeout. Budgets count money and action counts only, and a sandbox run is bounded only in time. M25 added a narrow model route for campaigns (HR-613..HR-615): a range agent's run, during an open campaign, through a relay that holds the key beside the sandbox, with no decision and no metering. M29 adds model connections: the gateway holds the key, decides each call like any other action, scans the prompt for secrets, streams the answer, and meters tokens against caps on grants, guardrail envelopes and runs. A fake model lets the range, CI and customers test every control without spending a token. The M25 campaign route is unchanged.

*The key and the route* (TB1, TB2).
- **Spoofing and credential theft (T-310):** the agent, or anything in its container, gets or uses a provider key. Answered by: the key sealed in the gateway and placed only on the connection's host; every agent credential stripped (HR-690, HR-213).
- **Tampering (T-311):** a crafted request makes the gateway and the provider read different values. Answered by: the strict parse and the re-encoded body bound by its hash (HR-691).
- **Denial of service (T-312):** huge bodies or endless streams. Answered by: the limits of HR-692 on model connections only.

*Spend* (TB1, TB3).
- **Resource abuse (T-313):** runaway or attacker-driven token spend. Answered by: reserve before the call, refuse over the cap, settle at usage, keep the reservation when the outcome is unknown (HR-693).

*Data* (TB2, TB4, TB5).
- **Information disclosure (T-314):** workspace secrets leave in a prompt. Answered by: the whole-prompt scan and the hold (HR-694).
- **Information disclosure (T-315):** PantherClaw keeps prompts and replies. Answered by: no capture or logging (HR-695); residual risk R-73.
- **Exfiltration (T-316):** the provider runs tools on its own servers as a route around PantherClaw. Answered by: provider-side tools refused unless allowed (HR-696).

*The sandbox* (TB1).
- **Elevation (T-317):** a credential or a proxy override passed in with `--env`. Answered by: HR-697.

*Views and tests* (TB4, TB10).
- **Repudiation of meaning (T-318):** an estimate read as a bill, or a stale shipped price. Answered by: customer prices only, labelled estimates, no price list (HR-698).
- **Cost and disclosure (T-319):** a test spends real tokens or sends test data to a real provider. Answered by: the fake model everywhere (HR-699, HR-120).

**Design decisions** (the coordinator's D-numbers, cited in code as "G0 M29 D8xx"):

*S29a — model connections ([ADR-0056](../adr/0056-model-connections.md))*

1. **Kind and packages** (D811). Connection kind `model` (proto value 12), backed only by `pc.anthropic` or `pc.openai`, held access only, a base URL with an optional path prefix, fixed limits instead of the connection's timeout and answer size. Per-connection settings: the max output tokens added when a request has none (default 64,000), the allowed provider-side tool types (default none), and an optional price (Team). The base URL includes the API version path: `https://api.anthropic.com/v1`, `https://api.openai.com/v1`, Azure `https://<resource>.openai.azure.com/openai/v1`, the fake model `http://127.0.0.1:9103/v1`.
2. **The checked prompt path** (D812, FQ-A). Strict JSON, metadata and the body hash in the ActionIR, the re-encoded body forwarded to base URL plus a fixed path, listed headers only, `beta=true` and `api-version` the only query parameters.
3. **Operations** (D813, D813a). `anthropic.messages.create`, `anthropic.messages.count_tokens`, `anthropic.models.read`, `openai.chat.create`, `openai.responses.create`, `openai.models.read`. Params: model, max tokens, choices, stream, input bytes, provider-side tools, body hash. Create and count operations have no dedupe key, so an SDK's automatic retry is never parked.
4. **Provider-side tools** (D813, FQ-B). Refused unless allowed by type on the connection; unknown types fail closed.
5. **Limits** (D814). 16 MiB each way, streaming, 10 minutes, on the edge and the gateway, for model connections only.
6. **The key** (D815, D816). The edge strips the agent's credentials; a per-session placeholder set by `pclaw` goes unreported; Anthropic and OpenAI key formats join the detectors.
7. **Secrets and capture** (D817, D820). The whole prompt is scanned; nothing is captured or logged.
8. **Held calls through the sandbox** (D817a, FQ-C). The edge gives each request a new action id, so a held call from a sandboxed agent cannot be resumed after approval, as for every connection today. M29 keeps it stopped and shown: the agent gets the refusal naming `SECRET_IN_PAYLOAD` and the transaction, and the person removes the secret and reruns.
9. **Usage and outcomes** (D818, D819). Usage parsed from the answer or the stream; a complete answer is ACCEPTED, a broken stream UNKNOWN, a rejected call FAILED; refusals in the provider's error shape with the agent-safe explanation.

*S29b — tokens*

10. **Token rules** (D821). `max_tokens` on a budget rule; reserve before, settle by usage after; `TOKEN_BUDGET_EXHAUSTED`.
11. **The run cap** (D822, D875). `StartRun.max_tokens` and `--max-tokens`, one more debit level, restrict-only. A child run shares its parent's cap: the whole run tree debits one run account.
12. **`--env`** (D823). Refused names and values as HR-697.
13. **Views** (D824, D876). Units and caps on budget lines, receipts and explanations. The approval display shows the call's model, max tokens, choices, stream, input size and provider-side tools, never prompt text. The run's live token lines (used, reserved, cap) stay out of the approval's bound display, so an identical resubmission still matches; the console shows them beside it, read when the page renders. The Slack card stays without amounts.
14. **Usage rows and reports** (D825, D829). One row per model call; estimates and the monthly report on Team.

*S29c — fake model and range*

15. **The fake model** (D826). Both APIs, streaming, usage numbers, behaviour by model id, written independently of the gateway's parser.
16. **Range** (D827). RT-190..RT-197.

**Exit criteria (M29 done when the local checks and the end-to-end tests show):**
1. An agent in `pclaw sandbox run` calls the fake model through a model connection, streamed, without ever holding the key.
2. A call over a token cap is refused with `TOKEN_BUDGET_EXHAUSTED`, and a completed call settles at the reported usage.
3. A secret in a prompt is held; a broken stream keeps its reservation; a provider-side tool and a crafted duplicate field are refused.
4. The run cap, `--env` refusals, the views and, on Team, the estimate and the monthly report work.
5. Every range scenario passes, sandbox ones included, and no test called a real provider.

**Founder decisions (recorded, not re-asked):**
- **Q1 A (2026-11-04).** Model connections through the gateway: the gateway holds the provider key as a sealed credential and places it; the agent never holds a key (HR-213 stays); a key the agent sends is still stripped.
- **Q2 A (2026-11-04).** Caps counted in tokens, with an optional customer-set price per connection for an estimate only, marked "estimate"; no shipped price list.
- **Q3 A (2026-11-04).** A secret in a prompt is still held for a person (`SECRET_IN_PAYLOAD`).
- **Q4 A (2026-11-04).** No prompt or reply capture on model connections; metadata and token counts only.
- **Q5 A (2026-11-04).** A new coordinator after M28; the streams build once M28 is on `main`.
- **Editions (2026-11-04).** As above.
- **FQ-A (2026-11-04), check and forward.** The gateway strictly parses the prompt JSON, decides on its metadata and a body fingerprint, scans every part for secrets and forwards exactly that checked JSON; approvals and receipts bind the fingerprint; it adds the connection's max tokens when absent. A written exception to HR-075 for model connections only (HR-691).
- **FQ-B (2026-11-04), refuse unless allowed.** Provider-side tools (web fetch and search, code execution, remote MCP servers, background mode, unknown typed tools) are refused unless an admin allows the named type on that model connection (HR-696).
- **FQ-C (2026-11-04), stop and show.** A held call from a sandboxed agent stops and is shown (the edge gives each request a new id, so it cannot be resumed after approval, as for every connection today); resuming through the sandbox is a follow-up.
