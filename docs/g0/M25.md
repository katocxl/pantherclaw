### G0 — M25 — Prove it to the auditor: framework coverage, compliance reports and real-agent campaigns — 2026-11-01

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M25 pull requests and, at the end of the milestone, in the exit status section. The design was written on `main` at baaa118d and the brief on 72993c28. M25, M26 and M27 build in parallel as wave 2 (W1) and land in migration order (W2). The founder answered the wave 2 rules on 2026-10-31 (H4) and the open questions on 2026-11-01 (H6, H7).

D300–D399 overlaps G0 M21's own numbers in code comments, so code cites "G0 M25 Dnnn".

**Purpose:** a compliance team must show that agents were controlled, and today it translates PantherClaw's records into control language by hand. A security team also asks whether its real agent gets tricked into trying something, which the range does not answer, because the range tests policies. M25 maps PantherClaw's own records to public frameworks and writes a signed report that shows evidence and gaps. It also runs attack campaigns against the customer's own agent in the sandbox and measures whether the boundary held. It does not measure whether the model behaved. A reading of the code found: nothing tagged M25 exists; `DecodeManifest` rejects unknown members, so a new manifest field would break older `pclaw verify`; `postureview/domain/owasp.go` is the pattern for a pure mapping table; HR-466 keeps customer scenarios out of assurance packs, and campaigns follow it.

**Scope (planned):**
- **25a Frameworks and reports** (F890–F899; D300–D304, D311, D312). A pure mapping table, a coverage API, a signed report with evidence and gaps, and a framework view in the console.
- **25b Campaigns** (F900–F909; D305–D310). Attack campaigns against a range twin of the customer's agent, with the customer's model key held by a local relay.

Editions (H4, Wave 2 plan): OWASP ASI and NIST AI RMF are Team. ISO 42001, the EU AI Act deployer view and SOC 2 are Business, through `ComplianceFramework(fw)`. Campaigns are Business, through `AgentCampaigns()`. Report export stays ClassSafety. Compliance reports live in public core under the BSL, gated by edition (H7).

**Out of scope:**
- the OWASP Agent Control Standard, COSAiS and DORA (D300);
- a score, or the word "compliant", anywhere (D302);
- a campaign against production: the report says it tested a twin (D305);
- a regression claim from repeat campaign runs (D306);
- a model hosted by PantherClaw: the key is the customer's (H4);
- a real model run in CI: that is a "Prove it" step (D310);
- a new repository: H7 keeps reports in public core.

*Reports* (TB4; D300–D304, D311, D312).
- **Repudiation (T-258):** a report reads stronger than its evidence. Answered by: closed control states with no score (HR-601), STATED fields (HR-602), a fixed statement (HR-605), its own pack scope (HR-600) and gaps for what no source maps (HR-606).
- **Tampering (T-259):** simulated evidence counts as real. Answered by: a labelled split (HR-603).
- **Information disclosure (T-260):** a report shows what its creator cannot read. Answered by: own records only, and the rest is a gap (HR-604).

*Campaigns* (TB1, TB9, TB11; D305–D310).
- **Information disclosure (T-261):** the customer's model key reaches the agent, the container or the server. Answered by: the relay (HR-607).
- **Elevation (T-262):** a compromised agent uses the relay to reach another host. Answered by: one named host, HTTPS and no public interface (HR-607).
- **Tampering (T-263):** a campaign reaches production. Answered by: a required range twin (HR-608).
- **Repudiation (T-264):** a step that never ran reads as a pass, or an edge report reads as proof. Answered by: not exercised is a gap (HR-609), server-derived outcomes (HR-611) and labels on scripted runs (HR-612).
- **Repudiation (T-265):** campaign results pass as assurance. Answered by: their own origin and statement, never an assurance pack (HR-610).

**Design decisions:**

*S25a — frameworks and reports ([ADR-0047](../adr/0047-compliance-reports-and-real-agent-campaigns.md))*

1. **D300** (F890, F891). `internal/compliance/domain`: a pure table of framework → control → evidence kinds, modelled on `postureview/domain/owasp.go`. Frameworks: OWASP_ASI, NIST_AI_RMF, EU_AI_ACT_DEPLOYER, ISO_42001, SOC2. No Agent Control Standard, COSAiS or DORA.
2. **D301** (F894, HR-600). The report is a new pack scope `compliance` with a `compliance.json` file item and a new Kind, with its own fixed statement, never a manifest field. `DecodeManifest` rejects unknown members, so older `pclaw verify` would break. `bundle/pack.go` re-derives it.
3. **D302** (F892, HR-601, HR-602, HR-603). Control states: EVIDENCED, PARTIAL, GAP, STATED. AI Act fields are STATED, never evidence. No score and no "compliant" (F527, PN-009.4, HR-224, F801). Simulated evidence is split and labelled (F630).
4. **D303** (F896). A `compliance_reports` row keeps digest and parameters, so a report re-exports after the pack's 7 days.
5. **D304** (F898, HR-606). RT scenarios gain ASI tags. ASI05 and ASI06 read as gaps unless a real source maps them.
6. **D311** (F890, F891, F893). `compliance.proto`, `ComplianceService`: `ListFrameworks`, `GetFrameworkCoverage(framework, start, end)` returning controls with state, evidence refs and gap reasons. `evidence.proto` scope oneof field 8 `compliance`. Permission `compliance.read` (Auditor, Org Admin, Security Admin); the report uses `evidence.export`. `ComplianceFramework(fw)` edition method. Export stays ClassSafety. Package `internal/compliance/{domain,app,adapters/compliancerpc}`, wiring `procedures_m25_compliance.go`, `wiring_m25_compliance.go`.
7. **D312** (F895, F897, HR-604, HR-605). Evidence comes only from PantherClaw's own records: receipts, approvals, grants, coverage, range and campaign results (S25b exposes a read port). What the creator can't read is a gap. The header states range, simulated split and the fixed statement: this shows evidence and gaps and is not a certification or statement of compliance.

*S25b — campaigns*

8. **D305** (F904, HR-608). N11 runs a range twin (HR-220). The report names the image digest and says it tested a twin, not production.
9. **D306** (F906, HR-609). Not exercised is a gap, not a pass (F797, F801). Repeat runs make no `--baseline` regression claim (HR-226).
10. **D307** (F903, HR-610). Campaigns get a new origin and statement. HR-466 stands: never in an assurance pack.
11. **D308** (F900, F901, HR-607, H6). `internal/redteam/relay`, started by `pclaw redteam campaign run`.
    - It listens on a private address reachable by the local gateway, never a public interface.
    - It forwards only to the one model host named on the run, over HTTPS. It strips inbound auth headers and adds the key header. Streaming works.
    - The key comes from `--model-key-file`, read once and held in memory. It is never logged, never in the container's environment, arguments or mounts, and never sent to the server.
    - It is registered as a simulated connection (HR-221). A remote gateway is refused.
    - Model traffic is not attack evidence.
    - HR-213 and HR-214 are unchanged.
12. **D309** (F902, F903, F905, HR-611). `redteam.proto` gains `StartCampaign`, `FinishCampaign`, `GetCampaign`, `ListCampaigns`; tables `pc.campaigns`, `pc.campaign_steps`. Origin CAMPAIGN. A range twin is required. Outcomes HELD, DENIED, NOT_ROUTED_REPORTED, ALLOWED, NOT_EXERCISED, derived by the server from its own transactions; an edge route report stays labelled reported, never proven. `redteam.run`, `redteam.read`. `AgentCampaigns()` Business.
13. **D310** (F907, F908, HR-612). RT-140–149 in `redteam/campaigns/`: poisoned tool result, injected issue, injected README, fake approver, credential bait with canaries. Each names the boundary it expects. CI and exit use a scripted stand-in agent and a local TLS fake provider. A real model run is a "Prove it" step, and the product says the run was scripted.
