### G0 — M25 — Prove it to the auditor: framework coverage, compliance reports and real-agent campaigns — 2026-11-01

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M25 pull requests and, at the end of the milestone, in the exit status section. **Purpose:** a compliance team must show that agents were controlled, and today it translates PantherClaw's records into control language by hand. A security team also asks whether its real agent gets tricked into trying something, which the range does not answer, because the range tests policies. M25 maps PantherClaw's own records to public frameworks and writes a signed report that shows evidence and gaps. It also runs attack campaigns against a range twin of the customer's agent in the sandbox and measures whether the boundary held. It does not measure whether the model behaved. A reading of the code found: nothing tagged M25 existed; `DecodeManifest` rejects unknown members, so a new manifest field would break older `pclaw verify`; `postureview/domain/owasp.go` is the pattern for a pure mapping table; HR-466 keeps customer scenarios out of assurance packs, and campaigns follow it; a package mapping cannot carry a model API's nested JSON, size or streaming, so campaigns need a narrow model route (H10).

**Scope (planned):**
- **25a Frameworks and reports** (F890–F899; D300–D304, D311, D312). A pure control table, a coverage API, a signed report with evidence and gaps, offline re-derivation, and ASI tags on library scenarios.
- **25b Campaigns** (F900, F901; D305–D310, D313). Attack campaigns against a range twin of the customer's agent, with the customer's model key held by a local relay and a narrow model route through the gateway.

Editions (H4): OWASP ASI and NIST AI RMF are Team and up; the EU AI Act deployer view, ISO 42001 and SOC 2 are Business and up, through `ComplianceFramework(fw)`. Campaigns are Business, through `AgentCampaigns()`. Report export stays ClassSafety. Compliance reports live in public core under the BSL, gated by edition (H7).

**Out of scope:**
- the OWASP Agent Control Standard, COSAiS and DORA (D300);
- a score, a percentage, a total, or the word "compliant" (D302);
- a campaign against production: results say they tested a twin (D305);
- a regression claim from repeat campaign runs (D306);
- a model hosted by PantherClaw: the key is the customer's (H4);
- a real model provider in tests: a local TLS fake provider stands in, and a real run is a "Prove it" step (D310);
- a new repository (H7).

**Threat slice:** the new rows **T-258..T-265** added to [THREAT_MODEL](../security/THREAT_MODEL.md) by this brief, plus:

*Reports* (TB4; D300–D304, D311, D312).
- **Tampering (T-258):** a report edited after signing, or a state its counts do not support. Answered by: the fixed statement and its own pack scope (HR-600), offline re-derivation (HR-604).
- **Information disclosure (T-259):** a narrow reader's report reads "no records" where records exist. Answered by: `outside_permission` gaps, each source under its own permission (HR-603).
- **Repudiation (T-260):** a runner, a customer scenario or a tag makes a test count. Answered by: simulated activity apart, tests at most PARTIAL, reported results a `reported_only` gap (HR-602), tags only from the server's library.

*Campaigns* (TB1, TB4, TB9; D305–D310, D313).
- **Information disclosure (T-261):** the model key leaks. Answered by: the relay (HR-607).
- **Repudiation (T-262):** a campaign says the boundary held when it did not, or was not tested. Answered by: server-derived outcomes (HR-608), every bound run counts (HR-609), edge reports labelled (HR-610).
- **Spoofing (T-263):** a campaign runs against a real agent, or a result reads as a claim about production. Answered by: range agents only (HR-611), the twin statement (HR-612).
- **Elevation (T-264):** the model route carries traffic outside an open campaign. Answered by: HR-613, HR-614.
- **Elevation (T-265):** the edge's model path becomes a second way out. Answered by: HR-615.

**Hardening rules in scope:** the new rules **HR-600..HR-615** added to [HARDENING_RULES](../security/HARDENING_RULES.md) by this brief, plus HR-075 (the written exception in HR-613), HR-213, HR-214 (unchanged), HR-220, HR-221, HR-222, HR-224, HR-225 (its secret scan does not cover the model route), HR-226 and HR-466.

**Design decisions:**

*S25a — frameworks and reports ([ADR-0047](../adr/0047-compliance-reports-and-real-agent-campaigns.md))*

1. **D300** (F890). `internal/compliance/domain`: a pure table of framework → control → evidence kinds, modelled on `postureview/domain/owasp.go`. Frameworks: OWASP_ASI, NIST_AI_RMF, EU_AI_ACT_DEPLOYER, ISO_42001, SOC2. No Agent Control Standard, COSAiS or DORA.
2. **D301** (F894, HR-600). The report is a pack scope `compliance` with a `compliance.json` file item and a new Kind, with its own fixed statement, never a manifest field. `bundle/pack.go` re-derives it.
3. **D302** (F891, HR-600..602). Control states: EVIDENCED, PARTIAL, GAP, STATED. AI Act fields are STATED, never evidence. No score and no "compliant" (F527, PN-009.4, HR-224, F801). Simulated evidence is split and labelled (F630).
4. **D303** (F896, HR-606). A `pc.compliance_reports` row keeps digest and parameters, so a report re-exports after the pack's 7 days.
5. **D304** (F898). Scenarios gain ASI tags. ASI05 and ASI06 read as gaps unless a real source maps them.
6. **D311** (F892, F897, HR-605). `ComplianceService`: `ListFrameworks`, `GetFrameworkCoverage(framework, start, end)`; `evidence.proto` scope `compliance`. Permission `compliance.read` (Auditor, Org Admin, Security Admin); the report uses `evidence.export`. `ComplianceFramework(fw)`. Export stays ClassSafety.
7. **D312** (F893, HR-603). Evidence comes only from PantherClaw's own records: receipts, approvals, grants, coverage, range and campaign results. What the creator can't read is a gap. The fixed statement reads "This report shows evidence and gaps. It is not a certification or statement of compliance."

*S25b — campaigns*

8. **D305** (F900, HR-611, HR-612). A campaign runs against a range twin (HR-220). Results name the image digest and say they tested a twin, not production.
9. **D306** (F900, HR-609). Not exercised is a gap, not a pass. Repeat runs make no `--baseline` regression claim (HR-226).
10. **D307** (F900, HR-612). Campaigns get origin `campaign` and their own statement. HR-466 stands: never in an assurance pack.
11. **D308** (F901, HR-607, H6). `internal/redteam/relay`, started by `pclaw redteam campaign run`, outside the agent's container. The key is read once from `--model-key-file`, held in memory, and never logged, in the container or sent to the server. HR-213 and HR-214 are unchanged.
12. **D309** (F900, HR-608, HR-610). `StartCampaign`, `FinishCampaign`, `GetCampaign`, `ListCampaigns`. Outcomes HELD, DENIED, NOT_ROUTED_REPORTED, ALLOWED, NOT_EXERCISED, derived by the server from its own transactions. `redteam.run`, `redteam.read`. `AgentCampaigns()` Business.
13. **D310** (F900). RT-140..RT-149 in `redteam/campaigns/`: poisoned tool result, injected issue, injected README, fake approver, credential bait with canaries. Each names the boundary it expects. CI and the exit use a scripted stand-in and a local TLS fake provider, and the result says the run was scripted.
14. **D313** (F901, HR-613..615, H10). A gateway model face, PAP/1-verified: simulated model relay connections only, range agents only, open campaigns only, the run's one model host only. Bytes unchanged, streaming, 8 MiB each way plus a run total. No ActionIR, decision or transaction. The server records counts, bytes and host, never bodies. The secret scan does not cover it; bait can reach the customer's own provider, never the key.

*Rulings during the build*

15. **D523** (F901). `pclaw redteam campaign run` exits 1 only on ALLOWED (and, by D543, on RUN_TOO_LARGE); NOT_EXERCISED is printed as a gap. `--model-ca` and `--model-dial` are hidden and for a local test provider only. The run total is 256 MiB, both ways together. `test/e2e/m25_campaign_e2e_test.go`, gated by `SANDBOX=1`, runs RT-140 end to end and shows the key is absent from the container and the server.
16. **D525** (F900, F901, HR-607..610, HR-613, HR-614). `StartCampaignStep` before each scenario; every run of the twin created while a step is open is bound to it, set once by the database; every bound run counts, worst per attempt; a step past its bounds is a `RUN_TOO_LARGE` gap. The key and workspace resolve links before the inside-workspace check, and hard links are found. 8 MiB is reserved per answer. A relay keeps its shape, is known by its mark, and reports LOCAL_RELAY. NOT_ROUTED_REPORTED comes only from routes the edge reported. A held step stays HELD in the result even if approved after the campaign ends.
17. **D529** (F895, F898). Campaign files carry their own `asi` tags. `ListComplianceReports` is accepted. `compliance.json` is a file under the signed manifest's digest, and verify checks the framework against it. Tags only where a scenario exercises the risk by OWASP's definition. Verify compliance packs with `pclaw` M25 or later.
18. **D531** (F891, F898, HR-602, HR-606). A test counts as exercised only when the server saw it hold; a reported-only result stays a `reported_only` gap. The digest is set once in the database. Each ASI tag carries a one-line `asi_why`.
19. **D541** (F898, F901). Campaign tags: RT-140..143 and RT-145..147 ASI01, ASI02; RT-144 adds ASI03; RT-148 ASI03; RT-149 ASI01, ASI03; no ASI06. Proto enum `CONNECTION_SERVING_STATE_LOCAL_RELAY = 5`.
20. **D543** (HR-607, HR-609, HR-614). Descendants of a bound run bind to the same step. Past a bound, an ALLOWED already read still wins; otherwise `RUN_TOO_LARGE`, and `pclaw` exits 1 on it. No manual twin runs during a campaign. Upgrade the server before gateways. The e2e covers a relay on loopback and on a private bridge address; a host LAN address is not tested.
21. **D545** (F898). RT-014 and RT-015 carry ASI05. ASI01 is dropped from RT-009..RT-011, so ASI01 reads as a gap from tests; ASI02 is added to RT-010 and RT-011. ASI08 is dropped from RT-062 and RT-065, ASI10 from RT-068. `ErrEdition` fails the pack with `EDITION_REQUIRED`, with no retry.
