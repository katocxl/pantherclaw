### G0 — M1 Platform foundation — 2026-10-08

This brief is written **before** implementation (G0). It lists planned scope; delivery status is tracked by the M1 pull requests and, at the end of the milestone, in FEATURES/HARDENING_RULES traceability.

**Scope (planned for M1):** everything listed for M1 in [BUILD_GUIDE §8](../BUILD_GUIDE.md#m1--platform-foundation): `platform/{clock,ids,errors,money,log,config,otel,crypto,keys,db,httpx,rpc}`, River setup, `evidence` part 1 (ledger + chainer + platform audit), `billing` part 1 (licence verification, edition limits, `pclaw-admin keygen|licence sign`), and `cmd/pantherclaw-server` (config, migrations, API + worker roles, health).
**Out of scope for M1:** any tenant business table beyond `orgs`; authentication (M2); Merkle checkpoints and anchoring (M7); entitlement metering (M13); a UI.

**Threat slice:** T-003 (tenant escape), T-016 (ciphertext swap), T-034 (licence forgery), T-041 (log injection / secrets in logs).
**Hardening rules in scope:** HR-004, HR-050..057, HR-062, HR-063, HR-104. HR-070..074 (egress client) are planned as part of `platform/httpx` in M1, with their tests, although they are scheduled for M1.5.
**Product requirements:** platform prerequisites for every pillar; no F-ID reaches *done* in M1.

**Contracts:**
- Migrations `migrations/00001…` (goose, SQL up + down) in schema `pc`: `orgs`, `ledger_entries`, `ledger_chain`, `ledger_heads`, `keys`, `deks`, `licence_state`, `cross_org_list_audit`, River tables (imported River SQL).
- Protos: `proto/pantherclaw/v1/system.proto` (`SystemService.GetBuildInfo`, unauthenticated, non-sensitive) to exercise the RPC stack.
- Licence document v1 (JWS compact, `typ: pc-licence+jwt`, EdDSA only).

**Security constraints and design decisions:**
1. **Database roles are bootstrapped, not migrated.** Roles are cluster-wide, and creating them from a migration would require `CREATEROLE` on `pc_migrator`. A one-time `pantherclaw-server db bootstrap` (run with the Postgres owner account) creates `pc_migrator` (owns schema `pc`, DDL only), `pc_app` (DML, `NOBYPASSRLS`, no TRUNCATE), `pc_audit_ro` (SELECT on evidence) and `pc_lister` (`NOLOGIN`, owner of the single audited cross-org lister). Migrations then run as `pc_migrator`.
2. **Session settings survive `RESET ALL`.** `statement_timeout`, `lock_timeout`, `idle_in_transaction_session_timeout` and `search_path` are sent as startup parameters, so `RESET ALL` on release restores them. `AfterConnect` verifies them (HR-057), `AfterRelease` runs `RESET ALL` (HR-052).
3. **Tenant context:** `InTenantTx(ctx, orgID, fn)` runs `SELECT set_config('app.org_id', $1, true)` first. A zero `OrgID` is rejected. `InGlobalTx` takes a registered purpose and never sets a tenant, so tenant tables return nothing inside it.
4. **Platform org.** Platform-level evidence (licence changes, key creation) is written under a reserved platform org (`00000000-0000-7000-8000-000000000001`), so there is one evidence mechanism. The zero UUID is never a valid org.
5. **Cross-org lister (HR-053/054):** one `SECURITY DEFINER` function `pc.cross_org_list(purpose, max_rows)` owned by `pc_lister` (BYPASSRLS, column SELECT only). It runs static queries chosen by purpose (no dynamic SQL), pins `search_path`, and writes a row to `cross_org_list_audit` per call.
6. **Ledger (HR-110 groundwork, ADR-0009):** entries are inserted unchained with `xid8 = pg_current_xact_id()`. The chainer takes a per-org advisory lock and chains entries whose xid is below `pg_snapshot_xmin(pg_current_snapshot())`, in `(xid, id)` order, into the insert-only `ledger_chain` table. `entry_hash = SHA-256(prev_hash ‖ canonical_entry)`. `ledger_heads` holds the head and the xid watermark. `ledger_entries` and `ledger_chain` have UPDATE/DELETE revoked from `pc_app` (HR-055).
7. **Envelope encryption (HR-062):** AES-256-GCM with random nonces, per-org per-purpose DEKs wrapped by a KEK from `KeyProvider` (file provider for dev). The AAD is a length-prefixed encoding of `(org, table, column, row id, purpose, DEK version)`.
8. **Licence (HR-063, T-034):** verified against Ed25519 public roots embedded at build time. Until the founder commits the offline-generated public key, no paid licence verifies and the server runs as Community. Behaviour (founder decision 2026-10-08): an expired licence keeps paid limits for a 14-day grace period with warnings, then drops to Community. A tampered or invalid licence drops to Community immediately and writes an audit event. Licensing never stops enforcement or startup.
9. **Logging (T-041):** JSON via slog; `Secret[T]`/`Sensitive[T]` redact; a `ReplaceAttr` denylist redacts sensitive keys; string values are capped at 2 KiB; control characters are escaped by the JSON encoder.
10. **Dependencies (founder decision 2026-10-08):** the newest versions outside the 7-day cooldown: `connectrpc.com/connect/v2 v2.0.0-rc.1`, `github.com/riverqueue/river v0.48.0`, `go.opentelemetry.io/otel v1.46.0`. `connectrpc.com/grpchealth` is not v2-compatible yet, so health uses plain HTTP endpoints until it is. OTel and recovery interceptors are written in `platform/rpc` instead of adding `otelconnect` (still in cooldown).
11. **Integration tests** use a Postgres admin URL (`PC_TEST_PG_ADMIN_URL`) from compose or a CI service container, with per-test databases cloned from a migrated template. `testcontainers-go` and `pgtestdb` are not needed.

**Dependencies to add:** pgx v5, goose v3, River (+ riverpgxv5), connect v2 rc.1, protovalidate, protobuf, go-jose v4, OTel (all already approved in DEPENDENCY_POLICY §3). New dev tools: sqlc, buf, protoc-gen-go, protoc-gen-connect-go (pinned under `tools/pins/`).

**Tests to write first:** `TestHR004_*` (conditional transitions), `TestHR050..057_*` and `TestT003_*` (tenancy, as `pc_app`), `TestHR062_*` / `TestT016_*` (AAD swap fails), `TestHR063_*` / `TestT034_*` (licence tamper, expiry, grace, unknown key), `TestT041_*` (no secret or control character reaches log output), `TestHR104_*` (protovalidate interceptor rejects invalid requests), chainer correctness (gaps, concurrent inserts, rollback), crypto known-answer tests.

**Open decisions:** none blocking. Items 1, 4, 5 and 6 are implementation choices within the approved ADRs and need founder confirmation at the first M1 PR.

**Deviations from the plan (for founder confirmation):**
1. **Role bootstrap is a command, not a migration** (decision 1 above).
2. **River migrations** run as goose *Go* migrations rendered from the pinned River module (River's SQL is MPL-2.0; nothing is copied into BUSL files).
3. **Health** uses plain `/livez` and `/readyz` because `grpchealth` is not connect-v2-ready.
4. **OpenTelemetry is API-only, and there is no `platform/otel` package.** RPC spans are created by `observeInterceptor` in `internal/platform/rpc/rpc.go`, but no SDK or exporter is wired, so nothing leaves the process: the OTLP/HTTP exporter pulls in gRPC and grpc-gateway (≈ 89 modules). **Open decision:** accept that dependency, write a small OTLP/HTTP-protobuf exporter, or export via logs only. *Answered 2026-10-10: keep spans API-only; the exporter is decided with production hardening (M13).*
5. **Chain latency** is bounded by the longest transaction in the PostgreSQL cluster (recorded in ADR-0009): run PantherClaw on a dedicated cluster.

**Still required for the M1 exit gate:** founder G1 on each PR and squash-merges to `main`; then tag `v0.0.1` to exercise the release pipeline (G2). Day-0 item 6 (offline licence root key) is needed before any paid licence can verify.

**Follow-ups:** move to connect-go `v2.0.0` after 2026-10-14; add `buf breaking` against `main` once protos exist there; add squawk (migration linter) to CI.
