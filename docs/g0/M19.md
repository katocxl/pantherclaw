**Purpose:** PantherClaw runs today as one server, one worker and one Postgres. Several replicas of the API are possible, but some of what they count and cache is per replica:
- The authenticated API's rate limits multiply with the number of replicas (R-58).
- Stream and wait caps multiply in the same way.
- A gateway certificate revoked on one replica can still be accepted on another for up to a second.
- A2A tasks created through one gateway replica are refused on another.

The database is a single host with no failover, and the worker must stay at one replica. A customer can only use PantherClaw-hosted gateways from a static list in the server's configuration. And each decided refund still takes about 17 database transactions.

M19 closes these gaps:
- Limits and caps hold across replicas.
- Every cache on the decision path has a stated staleness bound.
- The server survives a Postgres failover. It fails closed during the failover and never makes a decision without a read-write primary.
- Workers run with two or more replicas.
- A2A ownership is shared between gateway replicas like MCP state.
- PantherClaw can host one gateway process per organization on shared hosts, provisioned from records instead of configuration.
- The first refund of a budget period takes one transaction fewer.

In product terms this is Root ([PRODUCT.md](../PRODUCT.md)): the deployment gets redundancy and hosted gateways without weakening any decision-path guarantee.

*Limits and caches* (S19a; TB4, TB3; D201).
- **Denial of service (T-214):** a credential, session or caller spreads its requests or streams across replicas, so that per-replica limits and caps multiply. Answered by:
  - leased chunks of the shared counter, with the total bounded (HR-490);
  - stream and wait leases counted across replicas (HR-491).
- **Elevation:** a revoked gateway certificate accepted by another replica. Answered by: forgetting through `LISTEN pc_containment`, and otherwise the 1 s cache lifetime (HR-492).
- **Stale decisions:** a cache on the decision path serving data older than the fail-closed bound. Answered by: a stated bound ≤ 2 s or a LISTEN invalidation for every such cache, with one test each (HR-493, ADR-0040).

*Failover and workers* (S19b; TB5; D202).
- **Tampering / repudiation (T-215):** a promotion of an asynchronous standby loses committed revocations, containment changes or budget reservations, or two primaries accept writes (split brain). Answered by:
  - no decision while no read-write primary answers (HR-495);
  - after an asynchronous promotion, the maintenance hold with an epoch bump (HR-496, reusing HR-373);
  - `synchronous_commit=remote_apply` with one synchronous standby recommended for production;
  - `target_session_attrs=read-write`, so a connection never writes to a standby.
- **Spoofing:** a database host impersonated during failover. Answered by: TLS verify-full per host (HR-497).
- **Double work:** a job run twice by two workers. Answered by: every River job audited and made safe with two or more workers (HR-498).

*Hosted gateways* (S19c; TB3, TB7, TB9; D203).
- **Elevation (T-216):** one organization's gateway process reaching another's on the same host. Answered by:
  - one process per organization, with a certificate naming one organization (HR-499);
  - the isolation profile (HR-501).
- **Spoofing (T-217):** a hijacked host agent or a stolen enrolment token. Answered by:
  - the host identity has no organization authority (HR-500);
  - the token is single use and delivered only through the process's private tmpfs (HR-502);
  - deprovisioning revokes before it stops the process (HR-503).
- **Denial of service (T-218):** a noisy neighbour exhausting a shared host. Answered by: cgroup CPU, memory and pids limits per process, and a plan quota (HR-501).

*Decision speed* (S19d; TB5; D204).
- **Tampering (T-219):** a race between merged transactions overspending a budget. Answered by:
  - the merged transaction keeps the HR-001 and HR-048 order (HR-504);
  - a busy row gives `BUDGET_BUSY`, with at most one jittered retry (HR-505).

**Design decisions:**

*S19a — limits and caches (D201)*

1. **API limits (P1, R-58).**
   - Each replica takes leased chunks from `pc.rate_counters` (`Store.Take(n=k)`), with k = max(1, limit/16), and spends them locally.
   - A chunk expires at the end of its window.
   - On a store error, authenticated calls are refused, except the existing safety and allow classes (G0 M13 D27). HR-376 is unchanged.
   - R-58 closes.
2. **Per-instance caps (P2–P4).** The operations-stream cap per caller, the containment streams per certificate and the wait handles per instance are counted in migration 00226 `pc.stream_leases`.
   - Columns: org, kind, key, holder, id, `expires_at`.
   - A lease is inserted on open and counted in the same transaction, heartbeated every 10 s, expires after 30 s, and is deleted on close.
   - The wait handles' per-server limit stays local, as it bounds one process.
3. **authCache (P5).** The gateway certificate cache also forgets the entries of a revoked or disabled gateway on `LISTEN pc_containment`, which the containment hub already listens to. Otherwise the 1 s lifetime bounds it.
4. **Inbound limiters (P6–P10).**
   - These stay per replica, documented in R-66: the per-IP pre-authentication limits of the automation receiver, the OAuth and browser sign-in, and the extension web routes.
   - These move to the shared store: the per-transmitter signal limit and the evidence replay limit.
5. **Caches (P14).** ADR-0040 states each cache's maximum staleness. On the decision path it is ≤ 2 s, or the cache is invalidated through LISTEN. Each cache has one test.

*S19b — failover, workers, A2A (D202)*

6. **Database connections.**
   - `db.Config` takes several hosts, with `target_session_attrs=read-write` and TLS verify-full for each host.
   - A stable endpoint (a managed service or a proxy) is documented as the alternative.
7. **During failover:**
   - no decisions (`CANNOT_AUTHORIZE` / 503);
   - `/readyz` is false;
   - LISTEN reconnects and re-polls;
   - nothing is served read-only (G11).
8. **Replication stance.**
   - Production HA recommends `synchronous_commit=remote_apply` with one synchronous standby.
   - After an asynchronous promotion, the server starts in the maintenance hold with an epoch bump, reusing HR-373 (R-67).
9. **Workers.**
   - Audit every River job for safety with two workers, and fix those that are not safe (listed first, each in its own package).
   - Then default the Helm chart to `worker.replicas: 2` and add a worker PodDisruptionBudget.
10. **A2A ownership.**
    - Migration 00227 adds the kinds `A2A_TASK` and `A2A_CONTEXT` to `pc.gateway_mcp_state`, with M15's binding and caps (HR-411, HR-412).
    - A2A client and drift state, and the per-connection circuit breaker, stay per replica and are documented.
11. **Local failover test.**
    - A compose profile `failover`: two pinned `postgres:17` containers with a synchronous standby, on ports 5434/5435.
    - `TestFailover_*`, run through `task failover` under the heavy-run lock, checks:
      1. steady refunds through two gateway replicas;
      2. the primary killed;
      3. fail-closed answers during the gap;
      4. the standby promoted;
      5. reconnection, LISTEN resumed, containment within 2 s, the River leader re-elected, and no overspend or double execution;
      6. the asynchronous variant starts in the maintenance hold.
    - It is not a CI gate. The result is recorded in the exit pull request.

*S19c — hosted gateways (D203, G9)*

12. **Records.**
    - Migration 00228 `pc.hosting_hosts`: operator-level, no `org_id`, read through the cross-org lister.
    - Migration 00229 `pc.hosted_gateways`: with `org_id` and RLS, holding the host, state, `gateway_id` and resources.
13. **Provisioning.**
    - A worker job (the provisioner) creates the gateway and a single-use enrolment token.
    - The host agent `cmd/pantherclaw-host` pulls the token over its own mTLS identity: a new host certificate kind with no organization and the purpose `hosting`, which can never call organization RPCs.
    - It hands the token to the gateway process through a file on that process's private tmpfs, never an environment variable or a log.
14. **Isolation.**
    - One container per organization: a non-root uid, a read-only root, all capabilities dropped, no Docker socket, cgroup CPU, memory and pids limits, and its own network namespace.
    - It is started through the Docker CLI with fixed arguments (the HR-216 pattern).
    - No connector containers (HR-084 unchanged).
15. **Routing.** A per-org hostname `<slug>.gw.<domain>` with SNI passthrough, so the gateway's mTLS stays end to end.
16. **Plans.** Team plan and above, one hosted gateway per organization, with a plan quota.
17. **Upgrades.** The host agent rolls one organization at a time, with a health check, toward the target version of M18's fleet policy.
18. **Deprovisioning.** The host agent revokes the certificate (epoch) before it stops the process.
19. **Fallback.** The configuration list `gateways.pantherclaw_hosted` stays as a fallback for one release.

*S19d — decision speed (D204)*

20. **The merge.**
    - Only Prepare is merged into the snapshot transaction, for the first refund of a budget period or counter window.
    - Measure before and after, side by side on one machine, including M16's run read-history write.
    - Record the result in `docs/perf/M19.md`.
21. **Not done.** The Finalize + BeginDispatch merge is a follow-up founder decision, and the snapshot inside Finalize is rejected.
22. **Busy rows.** The lock timeout stays 100 ms → `BUDGET_BUSY`, and the gateway retries at most once, with jitter.
23. **Targets.** PN-011.1's p99 is a target, not a gate.
