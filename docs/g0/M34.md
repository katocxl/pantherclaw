### G0 — M34 — Cloud agent runtimes: the AgentCore face and interceptor, runtime runs, ADK and Foundry helpers, deploy and admin-command packages, daily discovery — 2026-11-05

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M34 branches and, at the end of the milestone, in an exit status section. M34 is code-only like M30–M33: every stream codes on pushed branches first, and testing (the HR and T rows below) comes later.

**Purpose:** a cloud agent runtime asks PantherClaw before it runs a tool. AgentCore asks through its request interceptor and the customer's own gateway. ADK agents, Vertex AI Agent Engine among them, ask through a callback, and Foundry apps answer MCP approvals from PantherClaw's decision. Agents deployed in those runtimes are found daily ([ADR-0061](../adr/0061-cloud-agent-runtimes.md)). Every decision is cooperative (PARTIAL, R-82, R-84).

**Founder decisions (2026-11-05, all recommended):**
- FQ34-1: the AgentCore interceptor asks the customer's own PantherClaw gateway, never the server directly. Raw tool arguments stay in the customer's network.
- FQ34-2: each AgentCore gateway is one PantherClaw agent, proven by its interceptor function's AWS role. Per-caller identity comes later.
- FQ34-3: discovery of agents deployed in AgentCore, Vertex Agent Engine and Azure AI Foundry runs daily and automatically. A person can still start a scan at any time.

**Coordinator decisions:**
- **D990 Channel `runtime`.** Cooperative (PARTIAL), DELEGATED like `authzen`, always `delegate` in dispatch and never forwarded; content signals scan it. `Mapper.Runtime` maps through the package's MCP mappings.
- **D991 Runtime target.** `pc.connections.runtime_target`, `agentcore:<gateway ARN>/<target name>`, unique per org, on kind `mcp` with custody `agent_held` only.
- **D992 Runtime runs.** `RuntimeService.StartRuntimeRun` for L2 instances enrolled by cloud attestation, under the issuer entry's run grant; audited `runtime.run_started`.
- **D993 Packages.** `pc.aws-agentcore`, `pc.vertex-agent-engine`, `pc.azure-foundry` (`agent.deploy`), `pc.aws-ssm` and `pc.azure-compute` (`code.execute`), reviewed, with no template grants. The Foundry API shape is unconfirmed.
- **D994 AgentCore face.** `POST /runtime/agentcore` before the HTTP proxy, PAP/1 as the hook face, `PC-Runtime-Gateway`. `tools/call` is decided through the connection bound to its target; `initialize`, `ping`, `tools/list` and `notifications/*` pass; other methods get -32601; HTTP events are refused. **D994a:** the gateway does the target lookup only, and the Authority refuses an account mismatch (`RUNTIME_ACCOUNT_MISMATCH`).
- **D995 Interceptor Lambda.** `cmd/pc-agentcore-interceptor`, standard library only: the Runtime API loop, `--local`, an in-memory Ed25519 key, `aws_iam` enrolment, a run per execution environment, a PAP/1 POST to the face, and a deny on any error. **D995a:** characters outside `[A-Za-z0-9._:/-]` in the run name become `-`, and an over-long name loses the end of its function part.
- **D996 Helpers.** `integrations/google-adk` (`pantherclaw_adk.before_tool_callback`) and `pantherclaw.foundry.FoundryApprovals`, both failing closed.
- **D997 Discovery and daily scans.** AgentCore runtimes, Vertex reasoning engines and Foundry agents; `pc.saas_scan_schedules` and a daily job; the `pc.runtime.agent_deployed` alert.
- **D998 Sims and seeds.** `internal/sim/agentcore`, `vertexagent` and `azure`; SSM and GetCallerIdentity in the aws sim; `dev_m34_runtimes.go`.
- **D999 Threat map.** `prevent.agent_deploy` (AML.T0103) and `prevent.cloud_admin_command` (T1651), surface GATEWAY, ALWAYS; AML.T0103 is also detected through `pc.runtime.agent_deployed`. The runtime face adds no control row.
- **D1000 Docs** as in this brief. **D1001 Streams and phases** as in the table above; code-only.

**Out of scope:** per-caller identity in AgentCore, AgentCore HTTP and Runtime targets, any live cloud run (testing and founder steps), and hosted gateways for the interceptor.

**Security constraints.** Fail closed everywhere: the face passes only an action recorded as delegated, and the interceptor and helpers refuse on any error. Keys stay in memory, and tool arguments are never logged. Wording follows HR-681's list in code, CLI and docs, and coverage is described as PARTIAL.

**Tests to write in Phase B:** `TestHR760_*`..`TestHR769_*`, `TestT345_*`..`TestT349_*`, RT-225..RT-229, and the ADK package's tests and lockfile.
