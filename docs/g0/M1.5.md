### G0 — M1.5 Walking skeleton — 2026-10-08

This brief is written before implementation (G0). It lists planned scope.

**Purpose:** validate the latency, chaining and budget designs end to end before building on them (BUILD_GUIDE §8 M1.5).

**Scope (planned):**
- `internal/actionir`: ActionIR v1 types, strict parsing (duplicate keys, unknown fields, depth and size limits, decimal-string amounts, ISO currencies, bidi controls rejected), RFC 8785 canonical form and `action_hash` (PAP-1 §6). Shared by the gateway and the Authority; pure.
- Migration: `org_containment` (epoch + kill switch), `budgets`, `budget_ledger`, `transactions`, `decision_receipts`, `permits`, `execution_attempts`; forced RLS like every tenant table.
- `internal/authority` (minimal):
  - **Authorize:** strict ActionIR, a hard-coded dev grant (operation `payments.refund.create`, at most 100.00 USD per refund), idempotency on `(org, run_id, action_id)` (same hash returns the stored decision; a different hash is `DENY ACTION_TAMPERED`), and one finalization transaction. It holds the containment epoch row `FOR SHARE`, makes a conditional budget reservation (`spent + reserved + amount <= limit_amount`), writes a transaction row, a permit row `ISSUED` (TTL 5 s from the **DB clock**, carrying the epoch), a signed decision receipt (ledger entry, chained later, HR-110) and the budget ledger. The permit is a JWS signed with the permits key.
  - **BeginDispatch:** one conditional UPDATE `ISSUED → DISPATCHING` only if unexpired by DB clock and the epoch is current (HR-001).
  - **RecordExecution:** accepted → reservation committed; failed → released; unknown → held with permit `UNKNOWN` (never released).
  - **Sweeper:** expired `ISSUED` → `RELEASED` with the reservation released; stale `DISPATCHING` → `UNKNOWN` with the reservation held (HR-003). It runs per org via the audited lister.
- `proto/pantherclaw/v1/authority.proto`: `AuthorityService` (`Authorize`, `BeginDispatch`, `RecordExecution`); ActionIR travels as canonical JSON bytes so both sides hash the same bytes.
- **Dev gateway authentication (clearly flagged, dev-only):** a static bearer token file maps to one org and one gateway id. The server refuses it unless the API listens on loopback. Real mTLS + org binding is M6 (HR-020).
- `pantherclaw-sim payments`: refund endpoint with fault injection (latency, failure rate, timeout rate) and duplicate detection by idempotency key; every response is marked `SIMULATED`.
- `pantherclaw-gateway` (minimal):
  - One hard-coded route, `POST /v1/refunds`. The dev workload identity comes from headers, clearly flagged; PAP/1 arrives in M3.
  - Request → ActionIR → Authorize → verify the permit (JWKS, `aud`, `exp`, action hash, epoch; HR-009) → BeginDispatch.
  - **Re-serialized** request to the target via the egress client (HR-070..075), with an idempotency key derived from the transaction id (HR-008), then RecordExecution.
- Load: a Go load driver (`pantherclaw-sim load`) for local measurement, k6 scripts for Linux/nightly, and the results in `docs/perf/M1.5.md`.

**Out of scope:** PAP/1 workload tokens (M3), real grants/policies/CEL (M4), approvals (M5), mTLS and org binding (M6), MCP.

**Threat slice:** T-010 (permit reuse after revocation), T-011 (overspend), T-012 (retry/tamper), T-021/T-022 (egress), T-024 (reservation leak after crash), T-031 (stale gateway, epoch part).
**Hardening rules:** HR-001, HR-003, HR-004, HR-008, HR-009, HR-070..075, HR-110.

**Tests to write first:**
- `TestHR001_BeginDispatchRejectsStaleEpoch` / `…ExpiredPermit`.
- `TestHR003_SweeperNeverReleasesDispatching`.
- `TestHR009_PermitIsSingleUse`.
- `TestHR075_OutboundIsReSerialized`.
- `TestHR008_IdempotencyKeyFromTransaction`.
- `TestT011_NoOverspendUnder1000ConcurrentReservations`.
- `TestT012_SameActionDifferentHashIsTampered`.
- `TestT024_CrashMidDispatchYieldsUnknown`.
- ActionIR fuzz and strictness tests.

**Exit:** p99 measured against the SLOs and recorded in `docs/perf/M1.5.md` (honestly labeled with the machine used); zero overspend at 1,000 concurrent reservations; crash mid-dispatch yields UNKNOWN with no release; an ADR update if the design must change.

**Open decisions:** none blocking. The dev gateway token is a deliberate stop-gap and is listed for removal in M6.

**Decision:** APPROVED in principle by the founder's instruction of 2026-10-08 ("M1, then M1.5"); confirmation at the first M1.5 PR — Joshua Kato

**Exit criteria:**
- **p99 measured against the SLOs and recorded with the machine used:** done. The SLOs were **not met** on the development laptop; see `docs/perf/M1.5.md`.
- **Zero overspend at 1,000 concurrent reservations:** met (`TestT011`). Every load run also kept each budget row equal to its ledger.
- **Crash mid-dispatch yields UNKNOWN with no release:** met (`TestT024`, e2e S07).
- **ADR update if the design must change:** [ADR-0015](../adr/0015-budget-settlement-off-the-hot-row.md) is **Proposed**, for founder decision.

**Deviations:**
1. The gateway was split into two slices (5 and 6) and end-to-end tests into slice 7, to keep each PR reviewable. Slice 6 is about 865 lines, about 400 of them tests.
2. "Budget last" was applied to `RecordExecution` and the sweeper after the measurements showed a cascade. This is a fix within ARCHITECTURE §6.3, not a design change.
