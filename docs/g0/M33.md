### G0 — M33 — Browser and computer-use agents: a managed extension behind a native host, the site list, secret fields, takeover and the computer-use gate — 2026-11-05

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M33 branches and, at the end of the milestone, in an exit status section. M33 is code-only like M30–M32: every stream codes on pushed branches first, and testing (the HR and T rows below) comes later.

**Purpose:** an agent that drives a browser or a desktop asks PantherClaw before it acts there. The managed extension holds each navigation, form submit, download and marked click and asks through `pclaw` on the machine. Unlisted sites hold for a person, secret fields are left to a person in a takeover, and computer-use actions are asked through the SDK wrappers ([ADR-0060](../adr/0060-browser-and-computer-use-agents.md)). The extension is cooperative (PARTIAL, R-78).

**Founder decisions (2026-11-05, all recommended):**
- FQ33-1: the extension reaches PantherClaw only through `pclaw` over Chrome native messaging. No key lives in the browser, and the gateway's Origin refusal stays.
- FQ33-2: an action on a site not on the org's list holds for a person, and an empty list holds every site.
- FQ33-3: the cloaking compare runs on the customer's gateway, for marked sites only. It is alert only and labelled PARTIAL.
- FQ33-4: an agent never types into or submits password, one-time-code or payment fields. There is no override: a person does that step in a takeover.

**Coordinator decisions:**
- **D974 `pc.browser`.** Target `browser.site` (the URL's host). Five irreversible operations, deduped by `params.call`, each with a hook tool: `browser.navigate`, `browser.form.submit` (field names, never values, and `secret_fields`), `browser.download`, `browser.click` (an element an admin marked) and `browser.takeover` (1..10 minutes). No template or default grant names one.
- **D975 Type `url`.** Printable ASCII, an absolute http(s) URL with a host and no userinfo, stored as `normurl`. CEL `normurl`, `urlhost` and `urlquery` return "" when invalid.
- **D976 Site list.** Migration 00370 `pc.browser_sites` and `BrowserService`, with the owned-accounts service's permissions and second-person rule. At most 500 per org, audited, and a change moves the gateway configuration version.
- **D977 Pipeline step `browser`.** An unlisted host holds (`SITE_NOT_LISTED`), an IP host never matches, an empty list holds all, and a takeover always holds (`BROWSER_TAKEOVER`). It only adds holds.
- **D978 Gateway refusal.** A submit with `secret_fields` is refused before the Authority is asked (`BROWSER_SECRET_FIELD`).
- **D979 Native host.** `pclaw browser host` (origin check, Chrome framing, 1 MiB in and 64 KiB out, 8 s per decide, `CANNOT_DECIDE` on any error) and `pclaw browser install-host` (configuration 0600, wrapper and manifest per OS). `hookPost` is factored out of the Claude Code hook.
- **D980 Extension.** `integrations/chromium-extension`. A dynamic redirect rule sends every top-level navigation to the hold page, and session rules let one decided navigation through. Submits, downloads and marked clicks are asked first. It fails closed and sends no page content.
- **D981 Secret and challenge fields.** Password, one-time-code and payment inputs are refused by type, `autocomplete` token, name pattern or a payment-host frame, and every event in a challenge frame is refused. Managed configuration can only add hosts.
- **D982 Takeover.** From the toolbar popup only. It is held for an approver and lasts at most 10 minutes. While it runs, the tab is let through and D981 is lifted.
- **D983 Policy generator.** `pclaw browser policy generate` writes `chrome-policy.json` and `chrome-policy.reg`: force-install and pin, incognito and guest off, the host name and the sites' click rules. It installs nothing.
- **D984 Computer use.** `pc.computer` `computer.input`, plus `ComputerUseGuard` in the Python and TypeScript SDKs and `guard_computer` for the OpenAI Agents SDK.
- **D985 Model route.** Declaring computer use needs `computer_use` in `allowed_server_tools` (`MODEL_COMPUTER_USE_NOT_ALLOWED`). Capture replaces images and documents by digests.
- **D986 Cloaking compare.** The gateway fetches an allowed page on a compare site twice, without cookies, and reports a mismatch with `ReportPageCompare`. The server writes `browser.cloaking_suspected`, and `pc.browser.cloaking` alerts only.
- **D987 Threat map.** Surface `BROWSER` and requirement `BROWSER_EXTENSION_DEPLOYED`. `prevent.browser_sites` maps AML.T0100 and AML.T0131, and `prevent.browser_secret_fields` maps T1696.001.
- **D988 Docs** as in this brief. **D989 Streams and phases** as in the table above; code-only.

**Out of scope:** browsers other than Chrome and Chromium, macOS policy generation (a follow-up), screenshots or page content as evidence, and any live browser run (testing and founder steps).

**Security constraints.** Fail closed everywhere: the extension acts only on an allow, the host denies on any error, and the site step holds without its list. No key in the browser and no page content out of it. Wording follows HR-681's list in code, CLI and docs, and coverage is described as PARTIAL.

**Tests to write in Phase B:** `TestHR745_*`..`TestHR759_*`, `TestT340_*`..`TestT344_*`, RT-220..RT-224, and the extension's own tests with its package.json and CI.
