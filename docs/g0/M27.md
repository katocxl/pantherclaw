### G0 — M27 — Agent Detection & Response: behaviour profiles, content signals, playbooks, SIEM packs and the read-only MCP server — 2026-11-01

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M27 pull requests and, at the end of the milestone, in the exit status section. The design was written on `main` at baaa118d and the brief on 72993c28. M25, M26 and M27 build in parallel as wave 2 (W1) and land in migration order (W2). The founder answered the wave 2 rules on 2026-10-31 (H4) and the open question on 2026-11-01 (H9). The brief settles two product boundaries, V5 and V6. In this brief "V5" and "V6" are those founder decisions (F789 against N12, F787 against N13), not the M22 graph views. The rows were rewritten from the streams' final text on 2026-11-03 (D556); the streams' numbers win over the first draft (D514).

**Purpose:** static rules miss slow misuse. Buyers expect a hook on tool results even though policy can't read meaning. A SOC knows how to handle phishing but not an agent incident, lives in its SIEM, and is building its own agents that need PantherClaw's records. M27 adds behaviour profiles on PantherClaw's own transactions, opt-in restrict-only content signals, a playbook library, SIEM packs and a read-only MCP server. None of it contains automatically on inference, and none of it claims anything is safe. A reading of the code found: nothing tagged M27 exists; `cohorts.Baseline` is not what N13 needs, so N13 uses `BehaviorProfile`; `pc.drift.behavior` and F399 are the existing drift hooks; `internal/outcomes/jobs.go` is the job pattern; `pc.transactions` is the source, not the ledger.

**Scope:**
- **27a Profiles** (F930–F935; D500–D502, D506). Behaviour profiles from the agent's own transactions, coded on simulated history, labelled inference, with approval context and a `basis` on alerts.
- **27b Content signals** (F936–F941; D503–D505, D507). An opt-in scan of tool results and outbound bodies that can only restrict.
- **27c Playbooks and packs** (F942–F945; D508, D509). Six playbooks in `hub/` and six SIEM packs built on OCSF export.
- **27d MCP server** (F946–F949; D510). `pclaw mcp self`, read-only, audited by the server.

Editions: N12 and N13 are Business. The N14 library is Team: all six playbooks run on Team (D554). N15 is Business, as the export. N16 is Team, `SelfMCP()`.

**Out of scope:**
- automatic containment on inference (H4, F800, D500);
- containment by a library playbook in M27 (D554): it returns when alerts carry a subject a playbook may act on;
- a decision reading a profile or an approval reading "never done X" (D501);
- logs from outside PantherClaw (V6, D506);
- a claim that content is safe (V5, F789, D504);
- a third-party classifier API adapter or a model inside the gateway (D503);
- the N16 assistant: it is parked, and HR-542 stands (H9);
- any write through the MCP server (H9, D510);
- store certification of a SIEM pack, and a forwarder that splits or verifies export batches (D509, D551);
- a customer's own SOAR acting on exported alerts: that is outside PantherClaw's control (D500).

*Profiles* (TB4).
- **Elevation (T-274):** an inference is used to contain, so a wrong guess or an attacker shaping an agent's behaviour suspends runs or revokes grants. Answered by: contain only on CONFIRMED alerts (HR-640), analytics off the decision path (HR-641), too little history infers nothing (HR-643), labels (HR-644), approval context outside the binding (HR-645), scoped reads (HR-646).
- **Tampering (T-275):** simulated data pollutes real data. Answered by: simulated history in its own table, compared only with simulated (HR-642).

*Content signals* (TB2, TB11).
- **Elevation (T-276):** a flag is abused to widen or to silently lose a restriction. Answered by: opt-in with a step-up (HR-647), restrict only (HR-648), no safety claim (HR-651), on through a lapse and a second person to leave ACTIVE (HR-652).
- **Information disclosure (T-277):** the scan stores or leaks content, drains the gateway, or is dodged by padding or stalling. Answered by: kind and location only, stored nowhere (HR-649), an incomplete scan holds (HR-650).

*Playbooks and packs* (TB4).
- **Elevation (T-278):** a signal drives a library playbook to contain a healthy run or revoke the wrong grant. Answered by: no library playbook contains (HR-653), the engine's confirmed-only contain (HR-640), packs that are data and ship disabled (HR-654).

*MCP server* (TB4, TB11).
- **Elevation (T-279):** a stolen Investigator key or a steered SOC agent reaches a write. Answered by: the role admitted on four reads only (HR-655), a closed tool list (HR-656), strict inputs (HR-659).
- **Repudiation (T-280):** a client skips the audit. Answered by: the server audits before the first response byte (HR-657).
- **Tampering (T-281):** record text steers the SOC's agent. Answered by: all record text labelled untrusted (HR-658) and agent-safe refusals (HR-659).

**Hardening rules in scope:** the new rules **HR-640..HR-659** added to [HARDENING_RULES](../security/HARDENING_RULES.md) by this brief, plus HR-030, HR-034 and HR-240 (no decision reads a profile), HR-222, HR-225, HR-284, HR-357, HR-400, HR-438, HR-542, HR-583 and HR-586.

**Design decisions:**

*S27a — profiles ([ADR-0049](../adr/0049-behaviour-profiles-on-own-transactions.md))*

1. **D500** (F933, HR-640). `reflex.alert` gains `basis`. The docs say that a customer's own SOAR on exported alerts is outside PantherClaw's control; exports carry the basis.
2. **D501** (F934, HR-645). "Never done X" shows beside the approval display, outside the binding, labelled inference. HR-030, HR-034 and HR-240 are unchanged: no decision reads it.
3. **D502** (F930–F932, HR-641..644). N13 reads `pc.transactions`, not the ledger, in a job per `internal/outcomes/jobs.go`. Simulated history is a labelled generator, split from real (F630, HR-222). Profiles say UNVALIDATED (F801). It extends `pc.drift.behavior` and F399, and uses `BehaviorProfile`, not `cohorts.Baseline`.
4. **D506** (F930, HR-641). V6(a): own transactions only.
5. **D514, D516** (F933, F943, HR-640). A contain step runs only on CONFIRMED alerts (OBSERVED or RULE_MATCH), library or custom. Otherwise it skips with `UNCONFIRMED_SIGNAL`; a definition on `alert.inferred` that would contain is refused (`CONTAIN_ON_INFERRED`). `revoke_grant` beyond EXECUTION skips only on an inferred trigger.
6. **D524** (F930, F931). `behavior.read` for Org Admin, Security Admin, Agent Owner, Approver, Responder and Auditor. The generator is a package only. Simulated signals are Test signals.
7. **D526, D547, D548** (HR-640, HR-643, HR-645, HR-646). Approval context compares with allowed actions before the held action, and needs the approval to be readable. The rollup pages by a keyset cursor, caps baselines per agent and raises `BEHAVIOR_CAP_REACHED`. Custom detection rules, and the Hub detection rules installed as custom rules, are capped at INFERRED. Validation warns `CONTAIN_NEEDS_CONFIRMED_ALERT` on a contain step under a trigger that is not an alert or incident.

*S27b — content signals ([ADR-0050](../adr/0050-content-signals-boundary-amendment.md))*

8. **D503** (F937, F940, HR-649). N12: V5(a) with its own F row and ADR-0050. Pure Go regex and entropy in the gateway; a port for an out-of-process classifier. No third-party API adapter, no in-process model. Findings keep kind and location, never value.
9. **D504, D552** (F941, HR-651). "No known flags", never "clean". Hook, SDK, AuthZEN and local faces and delegated outcomes show as not inspected.
10. **D505** (HR-652). On lapse an enabled signal stays on until a person turns it off (HR-357).
11. **D507** (F936–F940, HR-647..649). Port `ContentClassifier` in `internal/contentsignals/ports`; gateway `internal/gateway/contentscan`, bounded at 64 KiB, stored nowhere. A flag becomes a restrict-only fact on the run. Opt-in per organization, WATCHING first, then ACTIVE by step-up (HR-438 pattern).
12. **D512** (F936, F939, HR-648, HR-650, HR-652). ACTIVE fails closed as a `scan_incomplete` hold, with an owned failure; WATCHING counts would-be holds and the step-up shows them. A result flag holds later writes on the run tree, reads pass. `run.content_flags` lets an org's rule deny, never allow. Leaving ACTIVE takes HR-586's second person.
13. **D532, D533, D553** (HR-649..651). Pipeline version 7. A WATCHING flag stays on the run and holds later writes once the org moves to ACTIVE. The gateway sends a scan marker, and a gateway-carried call without it holds in ACTIVE. Unknown kinds become `scan_incomplete`. The raw body is always scanned; server-sent events get an extra pass. A classifier's location is kept only when it is the one asked about or one the built-in gives.

*S27c — playbooks and packs*

14. **D508, D539, D550, D554** (F942, F943, HR-653). N14: six playbooks in `hub/`. Install makes a draft. A playbook may contain only a subject its real alerts carry, on a CONFIRMED basis; no alert does today, so no library playbook contains in M27. Each signal playbook opens a case first, and all six run on Team. The range run is `TestRange_ScenariosPlaybooks`.
15. **D509, D536, D551** (F944, F945, HR-654). N15: `integrations/siem/{splunk,sentinel,chronicle,elastic,wazuh,sigma}`, Apache-2.0, built on OCSF export, tested offline on golden OCSF samples. Each README has an Ingest section and a "What was not checked" section. Sentinel and Wazuh need a forwarder that splits the batch, not built yet. No store certification.

*S27d — MCP server*

16. **D510, D517, D518, D522** (F946–F949, HR-655..659, H9). `pclaw mcp self`, stdio, tools `search`, `explain_decision`, `run_timeline`, `breach_radius`, in `internal/pclaw/selfmcp`. A service role, Investigator, admitted by a server interceptor only on WhatHappened, GetRunTimeline, Search and GetGraph; routes outside Connect that take API keys drop its bindings. The server audits every call of that role. All record text is labelled untrusted (HR-583). `SelfMCP()` Team.

*Exit*

17. **D511** (shared with G0 M25 and G0 M26). `test/e2e/m27_exit_e2e_test.go`: a simulated incident is detected, explained and contained by a person. Under an installed `scoped_incident_containment`, a CRITICAL inferred alert on a real agent skips contain with `UNCONFIRMED_SIGNAL`, and a person contains the run the alert names. `task range` runs.
