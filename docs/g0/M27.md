### G0 — M27 — Agent Detection & Response: behaviour profiles, content signals, playbooks, SIEM packs and the read-only MCP server — 2026-11-01

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M27 pull requests and, at the end of the milestone, in the exit status section. The design was written on `main` at baaa118d and the brief on 72993c28. M25, M26 and M27 build in parallel as wave 2 (W1) and land in migration order (W2). The founder answered the wave 2 rules on 2026-10-31 (H4) and the open question on 2026-11-01 (H9). The brief settles two product boundaries, V5 and V6. In this brief "V5" and "V6" are those founder decisions (F789 against N12, F787 against N13), not the M22 graph views.

**Purpose:** static rules miss slow misuse. Buyers expect a hook on tool results even though policy can't read meaning. A SOC knows how to handle phishing but not an agent incident, lives in its SIEM, and is building its own agents that need PantherClaw's records. M27 adds behaviour profiles on PantherClaw's own transactions, opt-in restrict-only content signals, a playbook library, SIEM packs and a read-only MCP server. None of it contains automatically on inference, and none of it claims anything is safe. A reading of the code found: nothing tagged M27 exists; `cohorts.Baseline` is not what N13 needs, so N13 uses `BehaviorProfile`; `pc.drift.behavior` and F399 are the existing drift hooks; `internal/outcomes/jobs.go` is the job pattern; `pc.transactions` is the source, not the ledger.

**Scope (planned):**
- **27a Profiles** (F930–F935; D500–D502, D506). Behaviour profiles on simulated history, labelled inference, with approval context and a `basis` on alerts.
- **27b Content signals** (F936–F941; D503–D505, D507). An opt-in port on tool results and outbound bodies that can only restrict.
- **27c Packs** (F942–F945; D508, D509). Six playbooks in `hub/` and SIEM packs built on OCSF export.
- **27d MCP server** (F946–F949; D510). `pclaw mcp self`, read-only, audited by the server.

Editions (H4, Wave 2 plan): N12 and N13 are Business. The N14 library is Team and custom playbooks are Business. N15 is Business. N16 is Team, `SelfMCP()`.

**Out of scope:**
- automatic containment on inference (H4, F800, D500);
- a decision reading a profile or an approval reading "never done X" (D501);
- logs from outside PantherClaw (V6, D506);
- a claim that content is safe (V5, F789, D504);

- the N16 assistant: it is parked, and HR-542 stands (H9);
- any write through the MCP server (H9, D510);
- store certification of a SIEM pack (D509);

*Profiles* (TB4; D500–D502, D506).
- **Elevation (T-274):** an inferred alert drives containment. Answered by: a `basis` on alerts and validation that refuses it (HR-640).
- **Spoofing (T-275):** inference misleads an approver, or simulated history reads as real. Answered by: context outside the binding (HR-641), own transactions only (HR-642), a labelled split (HR-643) and UNVALIDATED (HR-644).

*Content signals* (TB2, TB11; D503–D505, D507).
- **Information disclosure (T-276):** a found secret leaks through its finding. Answered by: kind and location only, stored nowhere (HR-647), and no third-party API or in-process model (HR-652).
- **Elevation (T-277):** a signal allows something, reads as clean, or goes quiet. Answered by: restrict only (HR-648), opt-in with a step-up (HR-649), honest wording (HR-650), stays on at lapse (HR-651).

*Packs* (TB4; D508, D509).
- **Elevation (T-278):** a playbook widens authority or contains too much. Answered by: install is a draft, and contain steps run only on CONFIRMED alerts on the trigger's run or grant (HR-653), with range tests (HR-654).

*MCP server* (TB4, TB11; D510).
- **Tampering (T-279):** record text steers the SOC's agent. Answered by: all record text labelled untrusted (HR-658).
- **Elevation (T-280):** the server reaches a write. Answered by: a closed allow-list (HR-655) and a read-only role (HR-656).
- **Repudiation (T-281):** a client skips the audit. Answered by: the server audits (HR-657).

**Hardening rules in scope:** the new rules **HR-640..HR-658** added to [HARDENING_RULES](../security/HARDENING_RULES.md) by this brief, plus HR-030, HR-034 and HR-240 (no decision reads a profile), HR-222, HR-357, HR-438, HR-542 and HR-583.

**Design decisions:**

*S27a — profiles ([ADR-0049](../adr/0049-behaviour-profiles-on-own-transactions.md))*

1. **D500** (F935, HR-640). `reflex.alert` gains `basis`. Automation validation refuses a contain step on an INFERRED alert (H4 is stricter than F800). The docs say that a customer's own SOAR on exported alerts is outside PantherClaw's control.
2. **D501** (F934, HR-641). "Never done X" shows beside the approval display, outside the binding, labelled inference. HR-030, HR-034 and HR-240 are unchanged: no decision reads it.
3. **D502** (F930–F933, HR-642, HR-643, HR-644). N13 reads `pc.transactions`, not the ledger. A job per `internal/outcomes/jobs.go`. Simulated history is a labelled generator, split from real (F630, HR-222). `definition_status` gains UNVALIDATED (F801). It extends `pc.drift.behavior` and F399. It uses `BehaviorProfile`, not `cohorts.Baseline`.
4. **D506** (F930, HR-642). V6(a): own transactions only.

*S27b — content signals ([ADR-0050](../adr/0050-content-signals-boundary-amendment.md))*

5. **D503** (F936–F938, HR-647, HR-652). N12: V5(a) with its own F row and ADR-0050. Pure Go regex and entropy in the gateway; a port for an out-of-process classifier. No third-party API adapter, no in-process model. Findings keep kind and location, never value.
6. **D504** (F941, HR-650). N12 says "no known flags", never "clean", and hook, SDK and delegated faces show as not inspected.
7. **D505** (F941, HR-651). On lapse an enabled restrict signal stays on until a person turns it off (HR-357).
8. **D507** (F937–F941, HR-647, HR-648, HR-649). Port `ContentClassifier` in `internal/contentsignals/ports`; builtin regex and entropy; an out-of-process adapter to a customer-run local service. Gateway `internal/gateway/contentscan` scans tool results and outbound bodies, bounded at 64 KiB, stored nowhere. A finding is kind and location only. A flag becomes a restrict-only fact on the run, read by later decisions: hold or deny, never allow. Opt-in per organization, Watching first, then ACTIVE by step-up (HR-438 pattern). Alerts are labelled inference.

*S27c — packs*

9. **D508** (F942, F943, HR-653, HR-654). N14: six playbooks in `hub/`: leaked key, poisoned MCP server, compromised laptop, rogue sub-agent, data-flow hold escalation, offboarded owner. Install makes a draft. Range tested. Contain steps only on CONFIRMED alerts, on the trigger's run or grant.
10. **D509** (F944, F945). N15: `integrations/siem/{splunk,sentinel,chronicle,elastic,wazuh,sigma}`, Apache-2.0, built on OCSF export, tested on golden OCSF samples. No store certification.

*S27d — MCP server*

11. **D510** (F946–F949, HR-655..658, H9). `pclaw mcp self`, stdio, tools `search`, `explain_decision`, `run_timeline`, `breach_radius`, in `internal/pclaw/selfmcp`. A closed allow-list of read procedures, tested so no write is reachable. A new service role `investigator`, read-only. The server audits every call of that set by that role (`wiring_m27_mcp.go`), so a client can't skip it. All record text is labelled untrusted (HR-583). `SelfMCP()` Team.

*Exit*

12. **D511** (shared with G0 M25 and G0 M26). A simulated incident is detected, explained and contained by a person. `task range` runs.
