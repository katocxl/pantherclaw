### G0 — M31 — Connector breadth: Google Workspace, Microsoft 365, Salesforce, Notion, Linear, model clouds, Snowflake and the OpenAPI importer — 2026-11-04

This brief is written before implementation (G0). It lists planned scope; delivery status is tracked by the M31 branches and, at the end of the milestone, in an exit status section. The founder approved a code-only phase on 2026-11-04: every stream codes on pushed branches first, and testing (the HR and T rows below) comes later.

**Purpose:** teams ask for the connectors their agents already reach: mail, files and calendars in Google Workspace and Microsoft 365, CRM and docs in Salesforce and Notion, issues in Linear, Anthropic models on Bedrock and Vertex, and Snowflake. M31 adds those packages on three shared contracts (richer HTTP dispatch, per-provider OAuth token URLs, Google service accounts) and an importer that drafts a package from an OpenAPI spec, which a person must review and sign before it loads.

**Scope:**
- **Dispatch extensions** (D950, F1005). JSON body keys may index arrays (`a[0]`) and build one object per list item (`a[*]`, identifier lists only, at most 64 items); a `graphql` dispatch sends a fixed document of at most 4 KiB with the body mapping as its variables; the `rfc5322-raw` encoding builds a plain-text mail message from `to`, `cc`, `bcc`, `subject` and `text`, and a line break in a header value or a separator in an address is refused when the params are decoded (`invalid_arguments` to the agent) and again when the message is built (`enforcement_failed`); fixed request headers stay literal and never `Authorization`, `Cookie` or `Host`.
- **Provider token URLs** (D951, F1006). An `oauth_client` credential's token endpoint is Microsoft's or Salesforce's (or a loopback simulator's), derived from the URL; anything else is refused when sealed and when opened.
- **Google service accounts** (D952, F1007). A new credential kind; the gateway signs a five-minute RS256 assertion per dispatch and exchanges it for one access token; the key never leaves the gateway and nothing is cached. `pclaw seal --google-service-account KEY.json [--subject] --scope …`.
- **OpenAPI importer** (D953, F1008). `pclaw package draft openapi` drafts an unsigned package from an OpenAPI 3.0 or 3.1 spec; the draft starts with `review_required`, which the package decoder refuses (`DRAFT_NOT_REVIEWED`). Every drafted write is irreversible and never retried, and its unknown outcomes are reconciled (D1208).
- **Spec simulator** (D954, F1009). `pantherclaw-sim openapi --spec FILE` answers every operation with its first example.
- **Packages** (D956–D962, F1010–F1019): see s31b and s31c.

**Out of scope:** OAuth flows that need a person (authorization code), Google user credentials, Swagger 2, external `$ref`s, GraphQL subscriptions, HTML or multipart mail, and any live provider run (testing and founder steps).

**Security constraints.** The agent never supplies a GraphQL document, a mail header line or a token endpoint. A drafted package is never loaded until a person removes `review_required` and signs it with an org key; names starting `pc.` are refused. Every new credential kind is minted per dispatch and placed only on the seal's bound hosts (HR-060). Wording follows HR-681's list in code, CLI, MCP and docs.
