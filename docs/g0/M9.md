**Purpose:** PantherClaw's promise is not "we have a gateway" but "this route is enforced, and here is the evidence". M9 makes coverage a computed, expiring claim. Every route by which an agent can cause an effect is inventoried per agent, connection and operation, and gets a state (`UNKNOWN`, `OBSERVE_ONLY`, `PARTIAL`, `ENFORCED`) derived only from evidence. `ENFORCED` comes from a containment sandbox: `pclaw sandbox run` puts the agent on an internal Docker network whose only route is a trusted edge sidecar that proxies HTTP(S), intercepts TLS with a per-session CA and signs PAP/1 to the gateway, so a raw `curl` to the GitHub API gets the same action and decision as the MCP route (F099). Signed probes and an external canary prove that every other route is closed, with controls, and the promotion expires. The same container machinery runs third-party MCP servers as connectors in customer-hosted gateways, with credentials injected by the edge. In product terms this is Checkpoint's coverage claim and Reflex's containment sandbox ([PRODUCT.md](../PRODUCT.md)).

**Founder decisions (answered 2026-10-11, the recommended option each time; recorded, not re-asked):**

1. Each sandbox gets its own internal Docker network (`gateway_mode_ipv4=isolated`; needs Docker ≥ 28, which raises HR-122's minimum from 26) holding the agent and a trusted edge sidecar.
   - The edge is the agent's only route and acts as its HTTP(S) proxy, intercepting TLS with a per-session CA.
   - The CA key exists only in the edge; the agent gets the certificate read-only.
   - The edge holds the run's workload key and signs PAP/1 to the gateway. A raw curl to api.github.com therefore gets the same action and decision as the MCP route (F099).
   - Unmapped hosts are refused.
2. Probes run in a separate container on the agent's network.
   - Results are signed with a per-session key that pclaw creates outside the sandbox, plus a server nonce.
   - The external canary is `pantherclaw-sim canary`, run outside the sandbox (on the host by default).
   - Positive and negative controls are required, and a failed negative control blocks promotion.
3. `ENFORCED` from sandbox evidence expires after 24 h (configurable). Any change to a connection, package, route, gateway or image drops it to `PARTIAL` at once. Stale coverage reads as `PARTIAL` and work continues.
4. HR-085 is reworded to the Docker equivalents:
   - its own container and namespaces, with a distinct non-root uid;
   - read-only root, cap-drop ALL, no-new-privileges, default seccomp, no host environment;
   - gVisor when available, detected and recorded, but not required for `ENFORCED`.
5. The customer-hosted gateway's host process launches connector containers through the Docker CLI with fixed arguments.
   - The Docker socket is never mounted into a container (HR-084).
   - Connector egress goes through the edge, which injects credentials.
   - Opaque MCP routes with mediated egress may go above the HR-086 `PARTIAL` cap, given probe evidence.
6. The coverage scope is agent × connection × operation. Exclusions are human-only and need a written reason and an expiry; they are audited.
7. Decision receipts gain an optional coverage claim (state plus snapshot id), checked by `pclaw verify` and by packs. Old receipts stay valid.
8. Use the Docker CLI with fixed arguments and add no new dependencies. Images are pinned by digest. Docker tests sit behind a build tag plus an environment variable and run with `task test:sandbox`. gVisor is detected and skipped on Docker Desktop.
9. F048 credential overreach compares declared permissions with used ones; for GitHub, the installation's real permissions. Findings go to a coverage findings table that M10 extends.
